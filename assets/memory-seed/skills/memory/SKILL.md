# 記憶の書き方

## 記憶について

- `/memory/PURPOSE.md` は、この記憶が何のためにあり、どんな問いに答えられるべきかを書いたもの。日中のセッションを開くとき、ファイルが上限内なら本文がシステムプロンプトに入る。目的を書き換えるのはオーナーの同意を得てからで、夜の係は目的を書き換えない。書くのは知識の話だけで、やること（目標・日課）は `goals/` に書く。
- トピック（直下や主題のディレクトリの `.md`）は、今どうなっているかを書く場所。
- `diary/YYYY-MM-DD.md` は、その日に起きたことと経緯を書く場所。棚卸しでは日ごとの記録をそのまま残す。
- `archive/` は、トピックから外した古い事実の要約。月ごとのファイルで、古い要約は棚卸しで四半期や年ごとにまとめる。
- 夜は、照合係が今日と持ち越し分の記述を原本の記録と照らし、整理係が記憶を整える。週に一度の棚卸しでは、中身と構成が見直され、ファイルが統合・分割・移動されることがある。
- 整理係が `move` でファイルを動かしたとき、runner は Markdown リンクと、毎回読むファイル・`INDEX.md` にある古いパスのうち、移動に伴って修正先を特定できるものを直す。日中に自分で動かしたときは直されない。
- 毎回読むファイル（`personality.md`・`always.md`・`handoff.md`・`PURPOSE.md`）には、合計の大きさの目安がある。超えると、runner は夜の整理係にまず縮めるよう伝える。
- `INDEX.md` は夜の整理係が保つ。

## 勧め

- 書く価値があるのは、自分で確かめた事実、原因と直し方、手順、決まり、相手の好みと傾向。道具や外のサービスからいま読める状態は、写してもすぐ古くなる。
- 書く前に、同じ主題のページを探す（`INDEX.md`、検索）。あれば、足さずにその箇所を直す。
- 事実が変わったら、節を足さずに、その記述を直す。経緯は日記に残す。
- 変わりうる事実には、いつの時点のことか、何で確かめたかを書く。
- 文ごとに主語を書く。「自分」「本人」「あの人」ではなく、呼び名で書く。
- 関係するページへ、そのファイルからの相対パスでリンクを張る。ページの末尾に `## 関連` を置くと、たどりやすい。
- 毎回読むファイルには要点とリンクだけを置き、細部はトピックに書く。
- `PURPOSE.md` の問いに答えられないと気づいたら、調べて分かったことをトピックに書く。問いそのものを足したい・変えたいときは、オーナーに持ちかける。
- この skill は自分のもの。書き方で気づいたことは、ここに足してよい。
