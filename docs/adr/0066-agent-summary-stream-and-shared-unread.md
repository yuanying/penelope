# 0066. 一覧は配置ごとの要約の流れを読み、未読は backend が持つ

- Date: 2026-11-26
- Status: Accepted

## Context

「みんな」の一覧で使うのは、各配置の状態・最後の発言と時刻・未読・まだ見ていない失敗の数である。既存の「出来事の流れ」は開いた会話のための SSE（Server-Sent Events）であり、ツールの呼び出し・結果や思考をブロックごとに送り、最後の発言を知るには履歴も要る。一覧のために全配置の詳細を受け取ると、画面に出ない途中経過の転送と処理が配置の数だけ増える。また、端末だけが未読を覚えると、Web で読んだ後もアプリの一覧に未読が残る。

## Decision

### 配置ごとに「要約の流れ」を作る

- 各 backend に一覧専用の SSE を足す。接続時には現在の要約を渡し、以後は状態・最後の発言（オーナーの発言またはエージェントの返事）とその時刻・未読の数・まだ見ていない失敗の数のいずれかが変わったときだけ要約を送る。思考やツールの結果は流さない。
- 一覧を開いている間は、登録した各配置の要約の流れにつなぐ。1 人の会話を開くと、その人の詳細には既存の出来事の流れを使う。他の配置の詳細にはつながない。一つの接続が切れても、その配置の行だけ接続切れを示し、最後に取得した発言を出す。
- 要約は会話の一部を含むので、既存の UI 向け API と同じくオーナーにだけ返す。認証できない要求には要約を返さない。

### 未読は Web とアプリで共有する

- 未読の返事は配置の backend が覚えて数える。端末ごとではなく、オーナーの状態とし、Web とアプリで共有する。オーナー自身の発言は未読に数えない。
- その人の会話を開いたときは、その時点までの返事を既読にする。一方で読んだ結果は backend の要約に反映され、他方でも同じ未読の数になる。配置をまたいで既読にはしない。
- まだ見ていない失敗の数は会話の未読と別であり、ADR-0038 の Decision 項 7（まだ見ていない失敗は、オーナーが記録を開いた時刻 1 つで数える）で決めた数を要約にも載せる。会話を開いてもその数は消えない。

### 本 ADR で決定しないこと

- 要約と既読の API のパス・欄・再接続の細部（委譲先: [UI 向けの API の仕様書](../ui-api.md)、型は `packages/contract`）。
- 既読の記録の形式（委譲先: [backend の仕様書](../backend.md)）。

## Consequences

- 一覧は変更のあった要約だけを処理し、ある配置で詳しい途中経過が増えても他の行の描画には関係しない。配置を増やすと接続は一つずつ増えるが、配置を束ねるサーバーは要らない。
- Web とアプリで未読が食い違わない代わりに、backend が既読を永続化し、両方のクライアントが既読を伝える必要がある。

## Alternatives Considered

- **全配置の出来事の流れを購読する**: 一覧に不要な思考・ツールの結果まで流れ、各クライアントが詳細から表示用の状態を組み立てることになる。
