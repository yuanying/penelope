# 0034. オーナーが送った画像も backend が写し、会話の履歴の行に結び付ける

- Date: 2026-11-17
- Status: Superseded by ADR-0078 and ADR-0079

## Context

オーナーは Web UI から、メッセージに画像やファイルを添えて送れる。ところが、送った画像は Web UI を読み込み直すと会話から消える。

前提になる事実は次のとおりである。

- 会話の履歴の 1 行のうち、オーナーのメッセージの行は文だけを持ち、添付を持たない。送った画像は、送ったブラウザがその場で持っているファイルから出しているだけである。読み込み直したブラウザや、別の端末のブラウザには、出すものが無い。
- 添付は、メッセージがなった出来事の中身として、backend が `/sources/ui/files/` に書く（ADR-0013）。`/sources` は sandbox が読む、届いた出来事の中身の置き場である。名前は出来事の番号を前に付けて書ける文字だけに直され、日付のファイルごとに保存期間を過ぎたら消す、と決めてある。
- エージェントの返事の画像は、backend が受けた時点で自分の永続する場所に写し、返事の行に結び付けて、ログインしたオーナーにだけ見せている（ADR-0032）。写しは変わらず、消さない。そこで決めた確かめ方は、種類を中身の先頭の bytes で見分けて Web UI がそのまま出せる画像に限ること、1 枚の大きさに上限を置くことである。1 回の枚数の上限は、返事の要求が sandbox から Sentinel を通って届くので、その大きさを抑えるために置いた。
- オーナーのメッセージには、ファイルの数の上限が無い。body の全体の大きさにだけ上限がある。

## Decision

適用範囲は、オーナーが Web UI からメッセージに添えて送ったファイルを、会話の履歴にどう残すかである。エージェントに出来事として渡す添付（`/sources` への書き込み）は変えない。

### 1. 画像は返事の画像と同じ置き場に写す

- backend は、オーナーのメッセージを受けた時点で、添えられた画像を、返事の画像と同じ「作ったものの写し」の置き場に写す（ADR-0032 の Decision 項 2（backend は呼んだ時点で写し、写しを返事に結び付ける））。`/sources` の添付とは別に持つ。
- 写しはオーナーのメッセージの行に結び付け、作ったエージェントを持たない（オーナーが送ったもの、と分かる形にする）。寿命は返事の画像の写しと同じで、消さない。
- 画像かどうかは、返事の画像と同じく中身で見分け、1 枚の大きさの上限も同じにする。

### 2. 画像でないもの、上限を超えるものは名前で残す

- 写さないファイル（画像でないもの、大きさの上限を超える画像）は、名前と大きさだけを行に残す。中身は持たない。
- オーナーのメッセージは、ファイルを理由に断らない。返事と違い、送り手はエージェントでなくオーナーであり、エージェントに届けることが先だからである。返事の 1 回の枚数の上限は当てない。オーナーのメッセージは Sentinel を通らず、body の全体の上限で大きさが抑えられている。

### 3. 出来事と行と写しは、まとめて残すか、何も残さない

- 写しを書けないときは、メッセージを受け付けず、出来事も列に入れない。エージェントには届いたのに履歴から画像が欠ける、ということが起きないようにするためである。
- 出来事を列に入れられないときは、行も写しも残さない。

### 4. Web UI は履歴の写しで出す

- 履歴のオーナーの行に、写した画像の一覧と、名前で残したファイルの一覧を載せる。画像そのものは、返事の画像と同じログインした UI 向けの口で ID から取る。
- 送った直後も、backend が受け付けた後は、読み込み直した後と同じく写しで出す。
- この決定より前に送られた画像は、写しが無いので戻らない。

### 守る対象と、失敗したときの倒し方

- 守る対象は、オーナーが送った画像と、backend の永続する場所である。
- 写しを作れるのは、ログインしたオーナーのメッセージの送信だけであり、見られるのもオーナーのログインのセッションだけである（ADR-0010）。
- 写しに失敗したときは、メッセージごと受け付けない側に倒す。

### 本 ADR で決定しないこと

- 履歴の欄の形と、メッセージを送った応答の形（委譲先: [UI 向けの API の仕様書](../ui-api.md) の「メッセージを送る」「履歴」）
- 写しの置き場所と表の形（委譲先: [backend の仕様書](../backend.md) の「作ったものの写し」）
- Web UI での見せ方（委譲先: [docs/design](../design/README.md) の「会話」）
- 画像でないファイルの中身を残すか（委譲先: その必要が出たときの ADR）
- 作ったものの一覧の画面にオーナーの画像を含めるか（委譲先: ADR-0032 の「本 ADR で決定しないこと」と同じく、その画面を作るときの ADR か UI 向けの API の仕様書）

## Consequences

- オーナーは、読み込み直しても、別の端末からでも、自分が送った画像を会話の中で見られる。
- 返事の画像と同じ置き場・同じ確かめ方なので、見せ方と寿命が 1 つで済む。
- 一方で、backend の永続する場所が、オーナーの画像の分だけ伸びる。同じ画像は `/sources` にも残るので、二重に持つ。
- 画像でないファイルは名前しか残らないので、読み込み直した後は開けない。
- 写しを書けないとメッセージごと送れないので、永続する場所が埋まると、オーナーは画像を添えたメッセージを送れなくなる。

## Alternatives Considered

- **Web UI が `/sources/ui/files/` の添付を読む**: `/sources` は届いた出来事の中身の置き場で、保存期間を過ぎたら消すと決めてある。名前も書き直されている。会話の履歴の表示がその寿命に引きずられる。
- **画像が上限を超えたら、メッセージごと断る**: オーナーがエージェントに伝えたいことが、見せ方の都合で届かなくなる。
- **画像でないファイルも中身ごと写す**: 任意の種類を同じ origin から配ることになり、見せ方の確かめが要る。今の依頼は画像を見せることで、名前が残れば足りる。
