# 0041. Signal のグループは、配置が許したものだけを、メンバー全員の発言ごと受ける

- Date: 2026-11-18
- Status: Accepted

## Context

Signal のプラグインは、許した相手との 1 対 1 の会話だけを受け、グループの発言は捨てている（ADR-0040）。オーナーが参加を認めたグループで、エージェントが家族や友人と話せるようにしたい。

- エージェントは、グループの会話の流れを読まないと、加わるかどうかを決められない。
- グループの発言の多くは、エージェント宛てではない。1 件ごとにターンを起こすと、会話の途中で何度も起きることになる。
- Signal では、連絡先の誰かがエージェントを承認なしにグループへ足せる。受ける側では防げない。
- Signal は、自分が送った発言を受信として返さない。
- penelope には、投稿の中身を判定する仕組みが無い（ADR-0033）。

## Decision

本 ADR は、Signal のプラグインが受けて送る先に、配置が許したグループを足す。ADR-0040 の、signal-cli との話し方と送り口の置き方は変えない。

### 1. 配置が許したグループだけを、メンバー全員の発言ごと受ける

- 設定の `groups` に、グループの名前と signal-cli のグループ ID を書く。書いたグループの発言・ファイル・リアクションは、送り主を問わず出来事にする。`stream` はグループごとに 1 つ。
- 書いていないグループの発言は捨てる。足されたことも知らせない。

### 2. エージェント宛てのものだけ `now`

- グループの発言は、エージェントへのメンション、エージェントの発言の引用、本文にエージェントの名前（設定の `names`）がある、エージェントがそのグループに送った直後の発言、のどれかなら `now`、ほかは `batch` にする。`batch` は backend の待ちの後にまとめて渡るので、会話が少し落ち着いてから読むことになる。

### 3. 送り口はグループにも送り、送ったものをグループの記録に入れる

- 送り口は、`groups` のグループにも送る。それ以外のグループには送らない。引用して返せる。
- グループに送った発言は、エージェント自身の発言（`own`）の出来事としてそのグループの `stream` に入れる。Slack でエージェント自身の発言を通すのと同じく、グループの流れに自分が何を言ったかが要るためである（ADR-0028 の Decision 項 3）。

### 守る対象と、失敗したときの倒し方

- グループのメンバーの発言は、オーナー以外の人の言葉である。受けるのは、配置が名前で書いたグループだけにする。
- グループへの送信は、1 対 1 と同じく判定を通さず、Sentinel の記録に残るだけである（ADR-0033）。
- 誰の送り先にも届かなかったときだけ、送り口は失敗を返す。

### 本 ADR で決定しないこと

- 設定の欄、`payload` の欄、`now` にする条件の細部（委譲先: [receivers の仕様書](../receivers.md) の「Signal のプラグイン」）
- 知らないグループに足されたときの扱い、グループへの投稿の判定と承認（委譲先: 足すときの ADR）

## Consequences

- エージェントが、許したグループの会話に加われる。
- オーナー以外の人の発言が、エージェントの記録（`/sources`）とモデルの入力に入る。どのグループを許すかは配置の判断になる。
- 知らないグループに足されても、気づかない。
- グループへの投稿は、エージェントの判断だけで出る。

## Alternatives Considered

- **グループでは、エージェント宛ての発言だけを受ける**: 会話の流れが分からず、加わるかどうかを決められない。
- **グループでも `senders` の発言だけを受ける**: オーナー以外のメンバーに答えられない。
