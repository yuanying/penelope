# 0077. 畳んだターンのツール呼び出しを、呼び出しと結果の組で残す

- Date: 2026-11-28
- Status: Accepted

## Context

runner は、終わったターンの履歴をモデルへ送り直す前に短くする。これを「畳む」と呼ぶ。これまで、返事以外のツール呼び出しは、呼び出しのブロックではなく `(folded)` で始まる地の文に置き換え、結果は省いていた。

本番で、小型モデルが履歴にある `(folded)` の行をまねて地の文を書き、ツールを呼ばずにターンを終えた。runner は地の文をツール呼び出しとして実行しない。

本番セッションの再生で、引数を途中で切る案では 130 応答中 3 回、新しい呼び出しの引数が省略記号 `…` で終わった。短い呼び出しはそのまま残し、長いものはツール名だけの履歴専用の呼び出しにする案では、96 応答で省略記号を末尾に持つ引数も、地の文での真似も 0 件だった。

## Decision

日中の本体セッションで終わったターンを畳むとき、ツール呼び出しを地の文に変えず、同じ ID の呼び出しと結果の組で残す。引数が上限以内なら元のツール名と引数をそのまま残す。上限を超えた場合は引数を途中で切らず、元のツール名だけを持つ履歴専用の呼び出し `folded` に置き換える。`folded` は実行できるツールの定義に加えない。

各呼び出しに対応するツール結果を一つ付ける。元の出力は送らず、出力だけを畳んだか、呼び出しも置き換えたかを定型文で示す。結果のない呼び出しにも定型文の結果を付ける。

`reply` と `reply_to_agent` は、実行結果があれば、引数と短い結果を従来どおり残す。思考は省く。出来事、地の文、ターンを畳む時点、元のセッション記録は変えない。

### 本 ADR で決定しないこと

- 引数の上限、履歴専用の呼び出しの引数形式、定型文の文面（委譲先: [sandbox API の「終わったターンの畳み込み」](../sandbox-api.md#終わったターンの畳み込み)）
- 畳む前の頼みを送る条件（委譲先: [ADR-0071 の Decision](0071-skip-the-fold-request-after-turns-without-tools.md#decision)）

## Consequences

- モデルは畳んだ呼び出しを、まねる対象の地の文ではなく、過去のツール呼び出しとして受け取る。
- 呼び出しごとに結果と識別子を送る分、地の文にまとめるより入力が増える。元のツール出力と、上限を超えた引数は送らない。畳んだツール履歴からは、長いコマンドの詳細を読み返せない。

## Alternatives Considered

- **引数を途中で切り詰める**: 再生では、省略記号が新しい呼び出しの引数に現れた。
- **呼び出しと結果を組ごと消す**: 外部へ送ったコマンドも履歴から消える。ペネロペの同じ 30 地点を使った 1 回の再生では、同じコマンドかパスを使う呼び出しが採用案で 3 回、組ごと消す案で 6 回だった。
- **畳んだ行を別の種類のメッセージへ移す**: 地の文とは区別できても、ツール呼び出しがあったことを API 上の呼び出しと結果の組で表せない。
- **`(folded)` の行を検知して知らせる**: 地の文を出力した後にしか対処できず、モデルにまねさせる履歴が残る。
