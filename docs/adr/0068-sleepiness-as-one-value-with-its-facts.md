# 0068. 眠気は backend が 1 つの値にし、元の事実と並べてターンの始まりと heartbeat に渡す

- Date: 2026-11-27
- Status: Accepted

## Context

本体のセッションは 1 本で、夜の切り替えで新しくなる。日中のコンテキストは、終わったターンの畳み込みと Pi の compaction で持たせる。compaction が走ると、ターンの前半の細部はモデルから見えなくなる。

エージェントは、自分のコンテキストがどれだけ埋まっているかも、前の切り替えからどれだけたったかも知らされない。ターンの入力に入るのは、届いた出来事と、直前のモデル要求の失敗などの runner の知らせだけである。本番の配置では、日中のターンは 1 配置あたり 40〜88 と開きがあった。切り替えの時刻はどの日も同じなので、文脈があふれる日も、ほとんど埋まらない日も、同じ時刻に切り替わる。

オーナーは、エージェントが「眠気」を持ち、それを自分で見て寝る時刻を決める形を求めた。眠気の元は 2 つである。コンテキストが増えると眠くなる。それとは別に、起きている時間が長いと眠くなる。

元の事実は 2 か所に分かれている。本体のコンテキストの量を知っているのは、Pi のセッションを回す runner だけである。backend が知っているのは、runner が知らせたモデルの候補のコンテキストの上限までである。一方、永続の状態と時計を持ち、Web UI と heartbeat を出すのは backend である。

残っている仕事を普段のターンに添えると、そのターンの用件以外にも注意を割かせる。このため、残っている仕事は heartbeat の行にだけ載せている。ターンの入力は畳んだ後も残るので、毎ターン添えたものは 1 日の文脈に積もる。

ここで使う言葉は次のとおりである。

- **眠気**: 起きている間に溜まり、眠ると抜ける 0〜100 の値。
- **元の事実**: 眠気を決める数。本体のコンテキストの量と上限、起きてからの時間。
- **status**: エージェントの今の様子として backend が持つもの。眠気と元の事実、気分、眠りの状態と起きる時刻。

## Decision

適用範囲は本体のセッションである。サブエージェントと夜の係のコンテキストは数えない。いつ、どう眠るかは [ADR-0069](0069-sleep-by-her-own-call-until-a-wake-time.md) が決める。

### 1. backend が眠気を 1 つの値にする

- backend が、元の事実から眠気を 0〜100 の 1 つの値にし、永続の状態として持つ。
- 眠気は、起きている間は下がらない。抜けるのは眠りでだけである。compaction でコンテキストの量が減っても、オーナーがコンテキストの上限の大きいモデルに替えても、眠気は下げない。
- 寝ている間は眠気を数えない。起きたら、起きてからの時間は 0 から数える。
- 眠気と自分で眠る仕組みは本体の機能であり、どの配置にもある。

### 2. runner は、コンテキストの量と上限をターンの終わりに知らせる

- runner は、本体のターンの終わりを backend に知らせるときに、そのときの本体のコンテキストの量と上限を足す。新しい口は作らない（ADR-0038 の Decision 項 1（ターンの結果ときっかけは、runner がターンの終わりの口で知らせる）と同じ伸ばし方である）。
- 数えるのは、畳んだ後にモデルへ送る量である。
- この数を知らせない runner と組み合わさったとき、backend は起きてからの時間だけで眠気を決める。

### 3. 同じ値を、どこにも使う

- backend は、同じ眠気を次のすべてに使う。エージェントに渡す知らせ（項 4）、Web UI とアプリに出す状態、metrics、限界を超えたら寝かせる安全網、receivers のプラグインが読む status である。
- どこに出すときも、値と元の事実を並べる。値だけを渡さない。

### 4. ターンの始まりと heartbeat に、事実として渡す

- 本体のターンの最初の入力に、runner が status を短い 1 つの知らせとして添える。置き場は、runner 由来のほかの知らせと同じである。ターンの途中に入る出来事には添えない。
- heartbeat の行にも status を載せる。
- システムプロンプトには status を入れない。値が変わるたびに prefix cache が外れるためである。システムプロンプトに書くのは、眠気が何であるかという事実だけである（ADR-0069 の Decision 項 8（システムプロンプトには、自分の様子がどう働くかを事実として書く））。
- 渡すのは事実だけである。いつ寝るべきかは書かない。
- 残っている仕事を heartbeat の行にだけ載せる判断（ADR-0055 の Decision 項 1（本体への heartbeat の行に直接載せる））は変えない。status を毎ターン渡すのは、寝るかどうかを自分で決めるために、どのターンでも要る事実だからである。

### 本 ADR で決定しないこと

- 眠気の式と、2 つの元の事実の重み（委譲先: [backend の仕様書](../backend.md)。眠りを実装する作業単位で節を足す）
- ターンの終わりに足す欄と、ターンに入る知らせの形（委譲先: [sandbox 向けの口の仕様書](../sandbox-api.md) の「ターンの終わり」と [出来事の仕様書](../events.md) の「ターンに入る形」）
- Web UI とアプリに出す欄と画面（委譲先: [UI 向けの API の仕様書](../ui-api.md) と [docs/design](../design/README.md)）
- システムプロンプトの文面（委譲先: プロンプトのファイル `packages/runner/src/prompts.ts`。ADR-0008 の方針に従う）

## Consequences

- エージェントは、どのターンでも、自分がどれだけ眠いかとその理由を知れる。
- 画面、metrics、安全網、エージェントへの知らせが同じ値を見るので、食い違わない。
- 一方で、ターンごとに知らせが 1 つ文脈に残る。眠気を伝える知らせそのものが、コンテキストを少しずつ埋める。
- ターンの始まりに渡る眠気は、前のターンの終わりに runner が知らせた数に基づく。長いターンの途中で増えた分は、そのターンには見えない。
- 眠気は起きている間は下がらないので、compaction の後やモデルを替えた後は、コンテキストの量から受ける印象より高い値が出る。
- 渡すのは事実だけなので、眠気が高くてもエージェントが寝るとは限らない。その床は安全網である。

## Alternatives Considered

- **runner が眠気を計算する**: コンテキストの量は手元にあるが、起きてからの時間、永続の状態、画面、metrics、安全網は backend にある。値を持つ場所が 2 つになる。
- **heartbeat にだけ載せる**: 出来事の多い日は heartbeat が来ない。眠気が溜まる日ほど、眠気を知れなくなる。
- **システムプロンプトに載せる**: 値が変わるたびに prefix cache を全部失う。
- **値だけを渡す**: なぜ眠いのか（コンテキストか、時間か）が分からず、判断の材料にならない。
