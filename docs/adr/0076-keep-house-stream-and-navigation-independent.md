# 0076. 人への配信は表示中の部屋で絞らず、入退室の応答で画面を移さない

- Date: 2026-11-28
- Status: Accepted

## Context

人の画面は、自分の部屋と覗き先だけの出来事を受け取るため、覗き先を変えると接続を開き直していた。新しい接続が開く前に入室すると、入室の出来事だけが先に届き、その前の発言が会話から抜けることがあった。

また、入室の応答を待って会話を開いていた。待つ間にブラウザーの「進む」で別の部屋を覗くと、遅い入室の完了がその画面とフォーカスを上書きした。

## Decision

### 1. ログインした人への配信範囲は、画面や居場所と分ける

人の画面は、全部屋の発言と出入りを同じ接続で受け取る。表示中の部屋や居場所が変わっても、配信範囲は変えない。家の設定で許可された人は、もともとどの部屋の履歴も読めるため、配信で読める範囲は広がらない。履歴と同じく、家が許可した人の同一オリジンの接続にだけ配信し、認証できない接続には配信しない。

入室せずに覗けることと、エージェントへの配信範囲は ADR-0075 の Decision 項 8（エージェントは、部屋の過去の会話を読めない）に従う。家の設定に登録した人だけが画面を開けることは、ADR-0075 の Decision 項 9（家は自分の画面を持つ）に従う。

### 2. 入退室の画面とフォーカスは、押したときに移す

入退室の応答と間取りの更新は、居場所の反映と失敗の通知に使う。その後に本人が選んだ画面とフォーカスは変更しない。発言できるのは、家が本人の居場所として示した部屋だけである。

### 本 ADR で決定しないこと

- 接続と履歴取得の手順、アドレスの形、失敗時に選べる操作（委譲先: 家の仕様書）

## Consequences

- 部屋を切り替える間も出来事を受け取り続ける。履歴を補う必要があるのは、まだ読んでいない部屋と、接続が途切れた間に抜けがあり得る部屋である。
- ログインしたタブが受け取る出来事は増える。その代わり、表示と接続の切り替えをそろえる必要がなくなる。
- 入室できなかった場合も、開いた画面から自動では戻らない。画面に失敗を出し、本人が次の操作を選ぶ。
