# 0038. 活動の記録は backend が 1 行の要約として持ち、ターンの結果と夜の段の結果を runner が知らせる

- Date: 2026-11-18
- Status: Accepted（一部を [ADR-0044 夜は記憶を原本と照合してから整理し、週に一度は棚卸しする](0044-check-memory-against-records-before-nightly-organization.md) と [ADR-0069 エージェントは `sleep` で自分で眠り、起きる時刻まで出来事を受け取らない](0069-sleep-by-her-own-call-until-a-wake-time.md) で置き換え）

## Context

Web UI に「活動の記録」の場所を作る。オーナーが後から、Pod のログを読まずに、各エージェント（本体とサブエージェント）がいつ・何をきっかけに・何をしたか、そして**何かが失敗していないか**を分かるようにするためである。見るだけで、操作（やり直す、夜の切り替えを手で回す）は置かない。

今の penelope で分かっていることは次のとおりである（References）。

- backend は、runner がブロックごとに送る途中経過（ターンの始まりと終わり、思考、ツールの呼び出しと結果、地の文）を SQLite に全部残している。消す処理は無く、増え続ける。過去の途中経過を読む UI の口は無い。
- ターンの終わりの口（`POST /v1/turns/end`）は `/memory` のコミットの合図で、ターンが成功したかを持たない。runner は、失敗したターンを自分のログに 1 行書き、そのターンの出来事を ack しないだけである。夜の切り替えは振り返り・整理係・新しいセッションの 3 段で（ADR-0007 の Decision「3 段は残す」）、整理係や振り返りのターンが失敗しても runner は先へ進む決まりである。その失敗も runner のログにしか出ない。
- 夜の切り替えは、runner が新しいセッションに切り替えた後に送る知らせ（`POST /v1/sessions/rotated`）の時刻だけが残る。どの夜の出来事の切り替えかも、段ごとの結果も残らない。backend が止まっていて夜の時刻を過ぎたときは、その夜の出来事を後から入れない（backend の仕様書「夜の切り替え」）。
- 裏の仕事の終わりは、runner が `POST /v1/job-events` で送る出来事で、始まりと終わりの時刻・終わり方・exit code・かかった秒・コマンドを持つ（ADR-0030）。
- サブエージェントは、runner が `POST /v1/agents` で起こした・閉じたを知らせ、backend が名前ごとに最後の知らせを残している（ADR-0022）。
- オーナーへの返事（`POST /v1/replies`）は、どのターンで出したかを持たない。
- 本番の配置で測った途中経過の量は、1 人 1 日 0.4〜2.2MB で、うち大半がツールの結果である。30 日分の全文で 1 人 50〜70MB、1 行の要約は 1 日 75 ターンとして 1 年で 1 人 10MB ほどの見込みである。backend の SQLite の置き場は 1 人 20Gi ある。

オーナーが決めたこと:

- 失敗を Web Push では知らせない。左のレールの「活動の記録」に、まだ見ていない失敗の数を出す。
- 1 行の要約は 1 年、ターンの中の流れは 30 日残す。ツールの結果の全文も、この 30 日のあいだは出す。
- トークン数と料金は出さない。

ここで「失敗」は、失敗したターン、止まった夜の切り替え、失敗した裏の仕事を指す。「止められた」ターン（Pod の停止などで runner が中断したもの）は失敗ではない。「逃した夜」は、夜の時刻を過ぎたのに切り替えが行われなかった夜である。

## Decision

夜の段の構成と記録する結果の範囲は [ADR-0044 夜は記憶を原本と照合してから整理し、週に一度は棚卸しする](0044-check-memory-against-records-before-nightly-organization.md) で拡張した。照合係の結果、各段の記憶の変更量、振り返りで引き継ぎが未更新だったことを加える。

適用範囲は、backend が持つ活動の記録と、それを満たすために runner が backend に知らせるものである。出来事の列・ack・やり直しの決まり（ADR-0002、ADR-0007）と、夜の 3 段そのものは変えない。

### 1. ターンの結果ときっかけは、runner がターンの終わりの口で知らせる

- runner は、ターンの終わりの口に、そのターンの結果（ふつうに終わった・失敗した・止められた）と、失敗したときの理由の 1 行を足して送る。
- 同じ口に、そのターンに渡した出来事の `seq` の並び（steer と follow-up で途中に入ったものを含む）を足す。backend はそれを自分の列の出来事と引き合わせ、きっかけの受信元と要約として残す。runner がきっかけの中身を送り直す必要は無い。
- 夜の切り替えのターン（振り返り・整理係）には、どの夜の出来事の、どの段のターンかを足す。
- 新しい口は作らず、既存の口を伸ばす。ターンの終わりは今もすべてのターンで送られており、結果が決まるのもその時だからである。

### 2. 夜の切り替えは、runner が段ごとの結果をまとめて知らせる

- runner は、夜の手順を 1 回回し終えるたびに、その夜の出来事の `seq` と、振り返り・整理係・新しいセッションの段ごとの結果（済んだ・失敗した・行われなかった）と、失敗の理由を知らせる。途中の段で止まったときも知らせる。
- 口は、今のセッションの切り替えの知らせを伸ばす。同じ夜の出来事がもう一度渡って手順を回し直したときは、その夜の記録を後の知らせで置き換える。手順を回さずに知らせだけを送り直すときは、段の結果を持たなくてよく、backend は前に受けた段の結果を残す。
- 整理係や振り返りが失敗しても先へ進む決まり（Context に書いた runner の決まり）は変えない。そのとき夜は、新しいセッションまで済んでいても「止まった夜」として失敗に数える。

### 3. 裏の仕事とサブエージェントには、新しい知らせを足さない

- 裏の仕事は、今の終わりの出来事が始まりと終わり・終わり方・exit code・かかった時間・コマンドを持つので、それで足りる。backend は受けたときに 1 行の要約を別に残す。
- 閉じたサブエージェントは、今の起こした・閉じたの知らせと、そのサブエージェントのターンの記録で足りる。
- 失敗した裏の仕事は、0 以外の exit code で終わったもの、時間切れで止めたもの、runner の送ったのでないシグナルで終わったものとする。エージェントが自分で止めたものと、runner の立ち上がり直しで切れたものは失敗としない。

### 4. 記録は、1 行の要約と流れの 2 段で持ち、期間で消す

- backend は、ターン・夜の切り替え・裏の仕事の 1 行の要約を、途中経過とは別に持つ。閉じたサブエージェントは、今あるサブエージェントの記録を使う。
- 1 行の要約は 1 年、ターンの中の流れ（途中経過）は 30 日で、backend が消す。消すのは backend の中の定期の仕事で、少しずつ消し、その間も UI の読み取りと runner の書き込みを長く止めない。
- 流れの消えたターンも、1 行の要約は残り、流れが消えたことが分かる。
- 返事は、それを出したターンに結び付けて残す。runner は返事の口にターンの ID を足して送る。足していない返事は、backend がそのとき本体の進んでいるターンに結び付ける。
- この版より前の記録は、途中経過から 1 行の要約を作って一覧に出す。結果ときっかけは「分からない」とする。前の夜の切り替えの記録は、段の結果が「分からない」夜として出す。

### 5. 古い runner と組み合わさっても backend は壊れない

- 結果・きっかけ・夜の段の結果は、どれも足した欄で、無ければ backend はそれを「分からない」として記録する。古い runner の要求を断らない。
- 終わりの知らせが来ないまま、同じエージェントの次のターンが始まったときは、前のターンを「止められた」とする。Pod ごと落ちて runner がターンの終わりを送れなかったときに、そのターンが進んでいるままに見えないためである。

### 6. 逃した夜は、予定と記録から読み出すときに決める

2026-11-27 追記: この項は [ADR-0069](0069-sleep-by-her-own-call-until-a-wake-time.md) で置き換え。夜の時刻の予定は無くなり、逃した夜の代わりに、眠りを求めたのに切り替えの知らせが来ない眠りを失敗に数える。

- 逃した夜は、記録には書かず、backend の夜の時刻の設定と、夜の出来事と、夜の切り替えの知らせから、読み出すときに決める。backend が止まっていて夜の出来事を入れられなかった夜も、後から出せる。
- 夜の時刻を過ぎて、その夜の出来事が無いか、出来事はあっても次の夜の時刻までに知らせが来なかった夜を、逃した夜とする。
- 逃した夜を出すのは、この記録が入った後の夜からとする。それより前の夜を全部「逃した」と出さないためである。
- 夜の時刻の設定を変えたときは、前の夜も今の設定で数える。

### 7. まだ見ていない失敗は、オーナーが記録を開いた時刻 1 つで数える

- backend は、オーナーが活動の記録の画面を開いた時刻を 1 つ覚える。ブラウザごとではない。
- その時刻より後に backend が知った失敗の数を、まだ見ていない失敗の数とする。逃した夜も数える（2026-11-27 追記: 逃した夜を数える点は [ADR-0069](0069-sleep-by-her-own-call-until-a-wake-time.md) で置き換え。眠れなかった眠りを数える）。日ごとの失敗の数には、逃した夜を数えない。
- 数が変わったら、UI の流れで新しい数を送る。開いたままの画面の札を直すためである。

### 守る対象と、失敗したときの倒し方

- 記録は、オーナーのログインで読む UI の口からだけ読める（ADR-0010）。sandbox からは読めない。
- 記録を残せなかったことで、ターンの終わりの合図（`/memory` のコミット）や出来事の受け取りを断らない。記録は見るためのもので、エージェントの動きを止める理由にしない。

### 本 ADR で決定しないこと

- 欄の名前・形・上限、口の道（委譲先: [sandbox 向けの口の仕様書](../sandbox-api.md) の「ターンの終わり」「セッションの切り替えの知らせ」と [UI 向けの API の仕様書](../ui-api.md) の「活動の記録」、型は `packages/contract`）
- SQLite の表の形、消す仕事の間隔と一度に消す量（委譲先: [backend の仕様書](../backend.md) の「活動の記録」）
- runner がどのときに「失敗した」「止められた」とするかの細部（委譲先: runner のコード `packages/runner/src/runner.ts` と [sandbox 向けの口の仕様書](../sandbox-api.md) の「ターンの終わり」）
- 画面の形、畳み方、きっかけの見出しの書き方（委譲先: Web UI の `packages/web` と [docs/design](../design/README.md)）
- 出来事・会話の履歴・作ったものの写し・`/sources` を消す期間（委譲先: 量が問題になったときの新しい ADR）
- 夜の切り替えを手で回すボタン（委譲先: 記録の実績を見てからの新しい ADR）

## Consequences

- オーナーは、ターン・夜の切り替え・裏の仕事の失敗を、ログを読まずに画面で知る。止まった夜と逃した夜も見える。
- runner の失敗が backend に届くので、「ack されずに次のターンでもう一度渡った」のような、ログでしか分からなかった動きが記録で追える。
- 30 日を過ぎたターンは、何が起きたかの要約だけになる。それより古い失敗の中身は追えない。
- 途中経過の全文を 30 日持つので、1 人 50〜70MB ほど SQLite が大きくなる。消す仕事が少しずつ動くので、読み書きは止まらないが、消した分の場所はファイルの中で使い回され、ファイルそのものは小さくならない。
- 逃した夜は今の夜の時刻の設定で数えるので、設定を変えた前後の夜は正しく出ないことがある。
- 古い runner の間は、結果ときっかけが「分からない」ターンが並ぶ。新しい runner に替われば、それからのターンには結果が付く。
- backend の SQLite の schema が進むので、この版の backend を前の版に戻すと、前の版は新しいファイルを開かずに止まる（今の migration の決まりのまま）。

## Alternatives Considered

- **ターンの結果と夜の段の結果のために新しい口を足す**: 終わりの口と同じ時に送るものを 2 つに分けると、片方だけが届く場合が増える。既存の口に欄を足せば、古い runner も今までどおり通る。
- **夜の段の結果を、段のターンのターンの終わりだけから backend が組み立てる**: 整理係のセッションを開けなかったとき、新しいセッションを開けなかったときは、ターンが無く、段の結果が届かない。
- **逃した夜を、backend が夜の時刻に記録として書く**: backend が止まっていた夜は書けない。読み出すときに予定と照らせば、止まっていた夜も出せる。
- **返事のターンを、いつも backend がそのとき進んでいるターンに結び付ける**: 途中経過は返事と別の道で送られるので、ターンの始まりより先に返事が届くと結び付かない。runner がターンの ID を送れば確かである。古い runner のためだけに backend の結び付けを残す。
- **「見た」をブラウザごとに覚える**: PC で見たあともスマートフォンに札が残る。オーナーは 1 人なので、backend に 1 つ覚えれば足りる。
