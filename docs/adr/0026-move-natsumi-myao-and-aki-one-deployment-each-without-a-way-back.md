# 0026. なつみ・ミャオ・アキも 1 人 1 つの配置で penelope に移し、記憶は履歴ごと写して、戻し道は持たない

- Date: 2026-11-16
- Status: Accepted

## Context

ペネロペは penelope で動いている。オーナーのエージェントには、ほかに秘書のなつみ、ミャオ、アキの 3 人がいて、natsumi（Pi Coding Agent の SDK を使う個人アシスタント）のインスタンスとして動いている。natsumi のコードと natsumi-sentinel（natsumi の関所）を使うのは、この 3 人だけになった。

オーナーは、3 人も penelope に移し、natsumi のコードで動く者をいなくすると決めた。penelope は最初からキャラクターに依存しない形で作ってある（ADR-0001 の Decision「コードはキャラクターに依存させない」）。名前・アバター・オーナーの呼び方は設定と記憶から取り、1 つの配置で動くエージェントは 1 人である。

3 人は、使うものが違う。

- なつみは秘書で、Slack の 2 つのワークスペースを受け、iPhone に通知を受け、オーナーの skill を持ち、ほかのエージェント（予定・メール・ニュース・調べものの係、ペネロペ、アキ）に A2A で頼む。
- ミャオは Slack の 2 つのワークスペースを自分の Slack App で受け、2 つの係に頼む。skill と iPhone の通知は持たない。
- アキは Slack を受けず、skill を持ち、調べものの係となつみに頼む。
- モデルの経路も違う。なつみとミャオは ChatGPT のサブスクリプションの経路（llm-proxy）、アキはローカルのモデルを使う。natsumi には、名前のついたモデルの経路を手で切り替える仕組み（natsumi ADR 0046）がある。

ペネロペを移したときの条件は ADR-0012 にある。並べて確かめる、記憶の書き手は常に 1 つ、記憶は履歴ごと写す、権限は新しい ServiceAccount に付け直す、戻せる形を保つ、本番の各段はそのつどオーナーの承認を取る、である。オーナーは 3 人については、問題が起きても natsumi に戻すのではなく penelope の側を直すと決めた。

Mac と iPhone のアプリは natsumi の v1 の封筒で話し、penelope の UI 向けの API（ADR-0009）にはつながらない。オーナーは、アプリを、penelope の全員をまとめて使える形で作り直すことを考えている。

## Decision

適用範囲は、なつみ・ミャオ・アキの 3 人を natsumi から penelope に移すことと、移した後の 3 人の配置である。ペネロペを移したときの条件（ADR-0012）は変えない。

### 1 人に 1 つの配置

- 3 人は、それぞれ penelope の配置を 1 つずつ持つ。どの配置も、このリポジトリの同じ image で動く。人ごとの違いは、配置の設定と記憶だけにする（ADR-0001 の Decision「コードはキャラクターに依存させない」）。
- 人ごとの違いのためにコードに分岐を足さない。要る違いが設定で表せなければ、どの配置でも使える設定を足す。
- Sentinel は別のリポジトリに切り出さない。どの配置も、このリポジトリの Sentinel を使う（ADR-0001 の「本 ADR で決定しないこと」の、Sentinel を切り出すかの答え）。

### 記憶は履歴ごと写し、書き手は常に 1 つ

- `/memory` は形が互換なので（ADR-0006）、中身を書き換えずに git の履歴ごと持ち込む。
- 写すときは、写し元の natsumi のインスタンスを止めてから写す。同じ人の記憶を 2 つの場所で同時に書き進めない。
- natsumi にしかない仕組みのファイル（penelope が読まない置き場）は、消さずに記憶に置いたままにする。片付けるかはエージェントに任せる。

### モデルは配置ごとに設定で選ぶ

- 使うモデルの経路は、配置の Pi のモデルの設定で決める。llm-proxy のほか、OpenAI 互換の API を持つ別の provider も使える。
- どの provider でも、鍵は sandbox にサロゲートとして置き、Sentinel が本物に差し替える（ADR-0004）。モデルの API のホストは Sentinel で開く（ADR-0003 の Decision「開くのは選んだホストだけ」）。
- モデルを手で切り替える仕組み（natsumi ADR 0046）は作らない。変えるときは配置の設定を変える。

### Sentinel は素通しのまま

- 3 人の配置でも、開くと決めていないホストの扱いの既定は素通しとする（ADR-0003 の Decision「既定の扱いは切り替えられる」）。
- なつみたちは、メールや予定などオーナーの暮らしの情報を扱う。素通しのあいだ、その情報をどの宛先にも出せることを受け入れ、Sentinel の記録を見てから ask に絞る。natsumi で使ってきた宛先の許可の一覧は、絞るときの allow の材料として配置のリポジトリに残す。

### 戻し道は持たない

- 3 人については、natsumi に戻す道を保たない。切り替えた後に問題が起きたら、penelope の側を直す。
- 切り替えた人の natsumi の配置とそのテストは、切り替えの後に消してよい。消す前に記憶の写しを確かめる。記憶の元の永続ボリュームを消すかは、そのつどオーナーが決める。
- 並べて確かめる期間も置かない。切り替えは、今の natsumi のインスタンスを止め、記憶を写し、penelope の配置を動かす順で行う。
- 本番に触る各段は、そのつどオーナーの承認を取る（ADR-0012 と同じ）。

ADR-0012 は「戻せる形を保つ」「並べて確かめる」を条件にしていたが、それはペネロペを移すときの条件であり、本 ADR の 3 人には当てはめない。ペネロペで penelope の形が日々の運用に耐えることを確かめた後であり、戻し道を保つと、natsumi のコード・natsumi-sentinel・2 つの配置を守り続けることになるためである。

### Mac・iPhone のアプリは後で作り直し、UI 向けの API はどの配置でも同じ形に保つ

- 移すあいだ、3 人との話し口は各配置の Web UI とする。natsumi の v1 の封筒の互換の口は作らない（ADR-0009 の Decision「最初は Web だけ」のまま）。
- 3 人の移行で、iPhone のアプリと APNs の通知は使えなくなる。通知は Web Push で受ける（ADR-0027）。
- Mac と iPhone のアプリは、後で penelope の全員をまとめて使える形で作り直す。それまで、UI 向けの API はどの配置でも同じ形に保ち、キャラクターや配置ごとに分岐させない。1 つのクライアントが、配置ごとの認証で複数の配置につなげる形を塞がない（ADR-0010 の Decision 項 1（オーナーは GitHub OAuth）の、アプリは後で Bearer の token で確かめる点）。

### 本 ADR で決定しないこと

- 移す順番と日取り、切り替えの手順（委譲先: 移行のタスクの記録と、配置のリポジトリ）
- 各人の配置の設定（モデルの provider、Slack のワークスペース、A2A の相手と送り手、skill、アバター）と鍵の置き場（委譲先: 配置のリポジトリ）
- 記憶の元の永続ボリュームを消す時期（委譲先: オーナーがそのつど決める）
- 既定を ask に切り替える時期と規則（委譲先: ADR-0003 の「本 ADR で決定しないこと」に挙げた、既定を ask に切り替えるときの ADR）
- 作り直す Mac・iPhone のアプリの形と、アプリ向けの token の発行の仕方（委譲先: アプリを作り直すときの ADR。ADR-0010 の「本 ADR で決定しないこと」）
- natsumi のリポジトリの扱い（委譲先: オーナー。全員を移した後に決める）

## Consequences

- natsumi のコードと natsumi-sentinel を守り続ける必要がなくなる。直すのは penelope の 1 つのリポジトリだけになる。
- 3 人が penelope の仕組み（Pi の基本のツール、Sentinel、サブエージェント、畳み込み）をそのまま使える。
- 記憶を履歴ごと写すので、3 人は今までの記憶のまま続けられる。
- 一方で、戻し道が無いので、切り替えた後に penelope に足りないものが見つかると、直すまでその人はその機能なしで動く。penelope に無い機能（Slack の受信、通知、裏の仕事など）は、その人を切り替える前に入れておく必要がある。
- 素通しの既定のあいだ、オーナーの暮らしの情報を持つエージェントが、どの宛先にも通信できる。natsumi の既定 deny より守りが弱くなることを、記録で気づく前提で受け入れる。
- iPhone のアプリと APNs が使えなくなり、作り直すまでは iPhone では Web Push と Web UI だけになる。
- モデルの手の切り替えが無くなり、経路を変えるたびに配置の設定を変えて Pod を作り直すことになる。
- 4 つの配置が同じ image で動くので、版を上げると全員が一度に変わる。1 人だけ版を止めることは、配置の image の版を分けることでしかできない。

## Alternatives Considered

- **ペネロペと同じく、並べて確かめてから切り替え、戻し道を保つ**: natsumi のコードと natsumi-sentinel と 2 つの配置を、移行が終わるまで守り続けることになる。ペネロペで penelope の形はすでに確かめてある。
- **Mac・iPhone のアプリのために、v1 の封筒の互換の口を backend に足す**: 作り直すと決めたアプリのために、古い形を持ち込むことになる。
- **モデルの手の切り替えを UI に戻す**: 経路を変えるのはまれで、配置の設定で足りる。
- **3 人は既定 deny で動かす**: 既定を ask や deny にする判定の部品（ADR-0005）はまだ形だけで、natsumi の許可の一覧を写して保つ仕組みが要る。記録を見てから絞る方を採った。
