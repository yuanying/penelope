# 0078. `reply` は今いる部屋か、出かけているときはオーナーに届ける

- Date: 2026-11-28
- Status: Accepted

## Context

エージェントは `reply` で配置ごとの Web UI に返事し、`house say` で家の部屋に発言する。オーナーは同じエージェントの言葉を二つの画面で読む。家では個人の部屋も定員のある普通の部屋で、どの部屋にもいない住人を「出かけている」と呼ぶ。最初の配置では、オーナーと一部のエージェントが家に住み、家に住まないエージェントもいた。家にいるときの会話と、出かけているときにオーナーへ言葉を届ける道を、家にそろえたい。

## Decision

### 1. 家が発言時の居場所で届け先を決める

- エージェントが部屋にいれば、`reply` はその部屋への発言になる。出かけていれば、設定で結び付けたオーナーへの 1 対 1 の発言になる。オーナーがどの部屋にいるか、家を開いているかは問わない。オーナーの居場所は入退室で決まり、ブラウザやアプリの切断・ログアウトでは変わらない。オーナーが切断中でも、同室への `reply` は部屋の履歴に残り、1 対 1 には切り替わらない。
- `reply` は `text`・`expression`・`images` に、部屋で呼びかける相手を示す任意の `to` を加える。部屋では `to` があっても同じ部屋の聞き手の範囲を狭めない。出かけている間は `to` を無視し、ほかの住人の名前を入れてもオーナー以外には送らない。部屋を指定する引数は取らず、家の発言に返信先の指定はないため `in_reply_to` も外す。
- `reply` の成功時は、届け先がどの部屋か、オーナーへの 1 対 1 かを返す。無視した `to` と、同室で発言が届かなかった住人も返す。応答を読めなくても家に発言が記録済みのことがあるため、自動で送り直さない。
- オーナーは相手の居場所にかかわらず、同じ 1 対 1 の欄を開いて履歴を読める。その欄から発言を送れるのは、相手が出かけている間だけである。部屋にいる相手との会話は部屋で行う。話す人数を絞るときは定員のある個人の部屋を使う。入室権限や人の覗き方を変える決定ではない。
- `house say` を廃止し、家の CLI は `status`・`enter`・`leave` だけにする。ターンの地の文は自分用の文のままで、会話に出さない。Slack と A2A の送受信はこの決定の対象外とする。

### 2. 1 対 1 は部屋と分け、答える口は `reply` にする

- 家は、部屋とは別にオーナーとエージェントの組ごとの 1 対 1 の履歴を持つ。入退室・定員・覗きは適用せず、部屋の発言の配信には混ぜない。位置が変わっても履歴の所属や、受け付けた発言の届け先は変えない。
- 家の受信元は引き続き `house` とする。部屋の出来事は既存の部屋 ID を `stream` に使い、1 対 1 は部屋 ID と衝突しない、組に固有の別の `stream` を使う。家の発言の本文は引き続き inline で渡す。
- 部屋では、`to` に入った受け手の発言の出来事にだけ `answer_via: {"tool":"reply"}` を付ける。部屋の届け方と睡眠中の扱いは変えない。オーナーからの 1 対 1 は受け手だけの `now` にし、同じ答える口を付ける。眠りを中断せず、起きるまで渡さない。家の届け待ちの期限と受領確認は引き続き使う。出入りには答える口を付けない。
- `reply` の発言は、部屋でも 1 対 1 でも送り手への出来事にしない。`reply` の引数は畳んだ履歴に残るため、自分の発言だけでターンを始める必要はない。`house say` を廃止するため、新版では家の自分の発言を戻す決まりもなくす。
- `reply` の届け先は、その呼び出しを受けた時点の居場所で決まる。出来事についた答える口は届け先を固定しない。以前の発言を別の会話に自動で引用・転送しない。

### 3. 家は発言と表情、画像の写しを一緒に持つ

- 部屋と 1 対 1 のどちらの発言にも、表情と画像を残せる。家の Web と iPhone は発言の表情に合うアバターと添付画像を表示する。表情は `neutral`・`happy`・`laughing`・`surprised`・`thinking`・`worried`・`sad`・`sleepy`・`angry`。表情がなければ、またはその絵がなければ、`neutral` を使う。表情ごとの絵は各 backend が配る既存のアバターを使う。
- 家は送信時に画像の写しを取り、発言と同じ SQLite に保存する。発言と写しを一緒に確定し、既存の家のバックアップでどちらも戻せるようにする。発言一件の上限は既存の `reply` と同じ 4 枚、1 枚 10 MiB とし、中身で判別した PNG・JPEG・GIF・WebP に限る。上限や形式に合わないとき、写しを保存できないときは発言ごと断る。
- 家が受け付ける上限は保存と転送の上限であり、モデルに画像を渡せる枚数とは別である。モデル要求に画像を載せる場合は、接続先ごとの上限に従って古い画像から省く。モデルの上限で省いた画像は家の履歴からは削らない。

### 4. 認証した送信者の発言だけを受け、誤った相手に送らない

- 守る対象は、発言・画像・履歴と、認証した住人に発言を帰属させることである。エージェントの発言は sandbox から Sentinel を通して家へ送る。家は既存のエージェント認証で送信者を確かめる。部屋の発言と画像は既存の閲覧と配送の権限の内側だけで配る。
- 家の設定だけが、エージェントごとのオーナーを一意に決める。家は送信者が受け手のオーナーかを確かめ、receivers のプラグインは家が付けた事実を `owner` の印に写す。プラグイン自身はオーナーを設定しない。1 対 1 は家が認証したそのオーナーだけが読み書きできる。エージェントには自分宛ての配送だけを許し、履歴を読む口は足さない。
- 居場所の確認と発言の確定を分けない。オーナーが 1 対 1 を送る間に相手が入室していたら、部屋には流さず断る。送信者を確かめられない、オーナーを一意に引けない、配置に家の設定が無い、または家に接続できないときは、送らずに失敗を返す。配置ごとの Web UI や別の住人へは送り直さない。
- `reply` が成功したら、runner は家の発言 ID とターン ID を backend に知らせ、活動の記録に結び付きを残す。活動の記録への通知に失敗しても、家に記録した発言は送り直さない。
- 切り替えに使うリリースは一つとし、旧・新の話し口を常用する期間は設けない。新しい `reply` を有効にする前に、オーナーが家で 1 対 1 と画像を確認できることを条件とする。残りの配置へ広げる前に、ペネロペとなつみで新しい話し口を確認できることも条件とする。ミャオの入居と話し口の切り替えは分けない。エージェント側の DB は移行しない。家に新しい記録を足しても旧版で既存の部屋の記録を読めるようにし、版を戻すだけで元の話し口に戻せるようにする。
- 全配置が新版になるまでは、1 対 1 に対応していない配置に 1 対 1 の出来事を渡さない。オーナーの画面では、その相手への 1 対 1 の送信を受け付けず、理由を示す。家は旧版のプラグインが読める形で部屋の出来事を配り続け、旧版の `house say` の受け口も残す。全配置が新版になったら、この互換の扱いを終える。

### 本 ADR で決定しないこと

- 家の API と `reply` の結果の欄、移行中に配置の対応を見分ける方法、`stream` の書式、添付の配り方、画像を出来事で受け取る契約（委譲先: [家の仕様書](../house.md) と [出来事の仕様書](../events.md)）。
- 家がアバターの表情ごとの絵を示す設定と配信の形（委譲先: [家の仕様書](../house.md) と [backend の仕様書](../backend.md) の「アバター」）。
- 個人のページと iPhone の接続（委譲先: 下記の ADR-0079 と ADR-0080）。

## Consequences

- 会話の履歴は家で読める。部屋で `reply` した言葉は同室の聞き手にも届く。内緒のつもりで `to` を使っても、宛先だけに聞こえるわけではない。
- 質問と答えが別の会話に分かれることがある。1 対 1 で聞かれたあとに入室して答えると、返事は同室の住人に聞こえる。逆に部屋で呼びかけられたあとに退室して答えると、返事はオーナーにだけ届き、部屋で聞いた住人には届かない。
- 相手が満員の部屋にいると、オーナーは家では話しかけられない。部屋に入れず、1 対 1 でも送れない。家の外では Slack で話せる。
- 部屋にいるエージェントからの警報や予約の知らせも、`reply` で送れば部屋に出る。オーナーが別の場所にいれば、その部屋の履歴を読むか通知を受けない限り気づかない。
- 家が止まると、部屋も 1 対 1 も発言できない。各配置のセッション・記憶と、Slack・A2A は家に依存しない。
- 各配置に分かれていた 1 対 1 の発言と画像が、家の DB とバックアップに集まる。画像の分だけ保存量が増え、家が侵害されたときに漏れる範囲も広がる。形式や上限に合わない画像を送るときは、送り手が直して送り直す。

## Alternatives Considered

- **1 対 1 を定員 2 の部屋にする**: 入室や覗きがない会話に、普通の部屋にはない例外を設けることになる。
- **画像は家の永続ファイルに置く**: SQLite を小さく保てるが、発言だけが確定した場合や、DB とファイルが別の時点まで復元された場合の扱いが要る。まず一緒に確定・復元できる置き場を選ぶ。
- **切り替え後も新旧の発言の道具を残す**: 同じ相手への発言で二つの道具と履歴を選ぶ問題が残る。
