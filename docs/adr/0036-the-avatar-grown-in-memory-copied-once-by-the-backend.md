# 0036. アバターは記憶の中で育て、最初の 1 回だけ backend が選んだアバターを写す

- Date: 2026-11-17
- Status: Accepted

## Context

アバターは、エージェントの名前・姿（絵を描くときのプロンプトの元）・表情ごとのアイコンの組である。表情のアイコンは Web UI・Web Push の通知・Slack の投稿のアイコンに出る（ADR-0016、ADR-0027、ADR-0033）。姿は、エージェントが自分の写った絵を `sdctl` で描くときに使う。

これまで、表情のアイコンは backend の image の中のアバター（リポジトリの `assets/avatars/`）から設定の名前で選んで読み、姿の素材（`appearance.yaml` と描画の既定の `sdctl-params.yaml`）は配置が sandbox に別に置いていた。アバターはリポジトリか配置の持ち物であり、エージェントは変えられなかった。

オーナーの要求は次のとおりである。

- 基本のアバターはこのリポジトリに入れ、配置は自分特有のアバターも足せる。
- アバターの姿などは、エージェントがオーナーの頼みで直し、育てていける。
- 将来、Mac・iPhone のアプリで 3D のモデルや動画のような大きな素材も出したくなったら、同じ置き場に置きたい。

エージェントが自分で書き換えられ、変更が履歴に残る場所は記憶（`/memory`）である。記憶は git のリポジトリで、backend がコミットし、sandbox からは `.git` を読むだけにしてある（ADR-0006）。backend は `/memory` の作業ツリーを読み書きでき、sandbox とは別のコンテナである。

backend は表情のアイコンを、ログインなしで外へ配る（Slack が外から取りにくるため。ADR-0033）。記憶の中のファイルはエージェントが自由に置けるので、アイコンとして配るファイルは、backend のコンテナの中の別のファイル（鍵や SQLite）であってはならない。

## Decision

### アバターの置き場は記憶の中にする

- エージェントのアバターは `/memory/avatar/` の 1 つのディレクトリに置く。中身の一覧を持つファイル（`avatar.json`）が、名前の既定と表情ごとのアイコンの場所を持つ。姿の素材も同じディレクトリに置く。
- 一覧は、知らない項目をそのまま残す形にし、素材の種類を後から足せるようにする。
- エージェントは `/memory/avatar/` を自由に書き換えてよい。変更は、記憶のほかの変更と同じく、ターンの終わりに backend がコミットする（ADR-0006）。

### 最初の 1 回だけ backend が写す

- backend は起動のとき、`/memory/avatar/` が無ければ（同じ名前のファイルもディレクトリも無ければ）、配置が選んだアバターを写し、写したものだけをコミットする。在れば中身を見ずに触らない。
- 写し元は、配置が mount する置き場と、backend の image の中の基本のアバターの 2 つで、配置の置き場を先に探す。配置がアバターを選んでいなければ写さない。
- どちらにも選んだアバターが無ければ、設定の誤りとして backend は起動しない。
- 写せなかったとき（`/memory` に書けないなど）は、backend は起動し、写し元のアバターをそのまま出す。次の起動でまた写そうとする。
- 写したファイルは、sandbox のエージェントが書き換えられる持ち主と権限にする。

### backend は読むだけで、確かめない

- backend は `/memory/avatar/` の一覧を、起動のときと、記憶のコミットのあと（ターンの終わり）に読み直す。エージェントが直したアイコンは、そのターンのコミットのあとから出る。
- backend はアバターを確かめず、使えない表情を出さないだけにする。一覧が読めなくても backend は落ちず、アイコンの無いエージェントとして出す。
- 使えるかどうかの規則を、エージェントにも渡す。sandbox の道具 `avatar check` は、backend と同じコードで `/memory/avatar/` を読み、何が使えないかを出す。規則のコードは backend と道具で 1 つにし、ずれないようにする。
- 直し方（置き場の形、姿・描画の既定・表情のアイコンの直し方、直したら `avatar check`）は、image の skill `avatar` で教える。システムプロンプトには入れない（ADR-0008）。

### ログインなしで配るのは、アバターの中の画像だけにする

- 守る対象は、backend のコンテナの中のアバター以外のファイルである。
- アイコンとして配るのは、リンクをたどった先が `/memory/avatar/` の中にある普通のファイルで、拡張子どおりの画像で、大きさの上限を超えないものに限る。`/memory/avatar/` そのものがリンクなら、何も配らない。
- 確かめられないものや、確かめに失敗したものは、配らない側に倒す（その表情は無いものとして扱う）。

### 名前は配置が決める

- エージェントの名前は、配置の設定にあればそれを使い、無ければアバターの一覧の名前の既定を使う。名前は backend の起動のときに決め、動いている間は変えない。
- 名前は UI・通知の題・A2A の Agent Card に出て、ほかのエージェントからの呼び名でもあるので、エージェントが育てるものに含めない。エージェントが育てるのは姿とアイコンである。

### 適用範囲

- 本 ADR は 1 つの配置の 1 人のエージェントのアバターに限る。サブエージェント（ADR-0022）はアバターを持たない。
- ADR-0006 の Decision「`/memory` の形を保つ」の固定のファイル名は変えない。`/memory/avatar/` は、エージェントが自由に切るトピックと同じく、固定のファイルの外に足すディレクトリである。backend のコミットに、ターンの終わりのほかに、起動のときの写しの 1 回が加わる。

### 本 ADR で決定しないこと

- 3D のモデルや動画のような大きな素材の持ち方（git で持つか、別の置き場か）（委譲先: そのときの ADR）
- 一覧の項目と画像の大きさ・形式の上限（委譲先: [backend の仕様書](../backend.md) の「アバター」）
- 配置の置き場の mount の仕方（委譲先: [Pod の仕様書](../pod.md) の「アバター」と配置のリポジトリ）
- 姿の素材の書き方（委譲先: image の skill `avatar` と `self-portrait`）

## Consequences

- エージェントは、オーナーの頼みで姿とアイコンを直し、その履歴を記憶の git に残せる。間違えたら履歴から戻せる。
- アバターを足すのに、リポジトリを直すことも image を作り直すことも要らない。配置の置き場に置いて選べば、最初の起動で記憶に入る。
- 一方で、写すのは最初の 1 回だけなので、記憶に入ったあとで配置の置き場やリポジトリの基本のアバターを直しても、そのエージェントには届かない。届けるには、エージェントに直させるか、`/memory/avatar/` を消して写し直させる。
- 移ってきた記憶にすでに `avatar/` という名前のものがあると、backend はそれをアバターとして読み、写さない。
- backend が確かめないので、壊れたアバターもそのままコミットされる。気づくのは、エージェントが `avatar check` を走らせたときか、オーナーが画面で見たときである。backend は使えない表情を出さないだけで、止まらない。
- backend は `/memory` の作業ツリーに書ける必要がある。書けない配置では、アバターは記憶に入らず、写し元のまま出て、エージェントは直せない。
- Web UI に出る名前は、エージェントが一覧を書き換えても次の起動まで変わらない。

## Alternatives Considered

- **sandbox の起動のときに、決まった置き場（記憶の外）へ写す**: 置き場がコンテナの中なので、コンテナを作り直すたびに image のアバターに戻り、エージェントが直したものが残らない。履歴も残らない。
- **backend がアバターを確かめ、壊れていたら直前のものを使う**: 何を「直前の正しいもの」とするかを backend が持つことになり、記憶を検査しない ADR-0006 の方針と食い違う。エージェントに確かめる道具を渡せば足りる。
- **名前もエージェントが育てる**: 名前はほかのエージェントや通知の宛先の側の呼び名でもあり、エージェントが変えると呼び名が配置ごとにずれる。
