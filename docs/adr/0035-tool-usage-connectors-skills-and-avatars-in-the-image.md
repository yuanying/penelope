# 0035. 道具の使い方の文書・共通の skill・姿の素材は sandbox の image に入れ、配置の文書は同じ名前で重ねる

- Date: 2026-11-17
- Status: Accepted

## Context

コネクタは、Sentinel のホストの登録と、その使い方の文書の組である（ADR-0020）。ADR-0020 は文書の中身を配置のリポジトリに置くと決めたので、このリポジトリはコネクタの文書を 1 つも持っていない。

配置を 4 つ（ペネロペ・なつみ・ミャオ・アキ）作ってみると、文書の大半はどの配置でも同じ「道具の使い方」だった。

- backend の文書は 4 つの配置で同じ中身である。
- Slack の文書は 3 つの配置にあり、違うのはワークスペースの名前と token の環境変数の名前だけで、`slackctl` での読み方・投稿の仕方・外の人の書いたものの扱いは同じ写しである。
- 絵を描く（`sdctl`）文書と、ほかのエージェントに A2A で頼む（`a2a` の CLI）文書も、宛先の一覧を除けば同じことを書いている。

この写しは、道具がこのリポジトリの中にある（`slackctl`）か、このリポジトリの image が版を決めて入れている（`sdctl`・`a2a`・`gh`）にもかかわらず、配置の側で道具の版に合わせて直さなければならない。また、私的な配置のリポジトリを持たない人は、公開のこのリポジトリだけでは道具の使い方を渡せない。natsumi を使っている人が、このリポジトリだけで移れるようにしたい。

skill にも同じことが起きている。自分の姿で絵を描く skill `self-portrait` と、目標と今日の計画を扱う skill `goals` は、どの配置でも同じものを、配置の init がオーナーの skill として置いている。runner は、オーナーの skill と記憶の `skills/` を並べて読み、同じ名前ならオーナーの方を一覧に載せる（Pi は同じ名前の skill の最初の 1 つを残す）。

姿の素材（絵に描くときの姿の `appearance.yaml` と、描くときの `sdctl` の既定の `sdctl-params.yaml`）は、配置がアバターごとに写して sandbox に置いている。一方、同じアバターの顔のアイコンは、このリポジトリの `assets/avatars/<名前>/` にあり、backend の image に入って、backend の設定で選ばれる（ADR-0016）。1 つのアバターの素材が、2 つのリポジトリに分かれている。

今ある 4 つの配置は、汎用と重なる文書・skill・姿の素材を持ったまま動いている。

## Decision

本 ADR は、ADR-0020 の Decision「中身は配置が持つ」のうち、このリポジトリが文書の中身を持たないとした点を置き換える。コネクタが登録と文書の組であること、一覧をシステムプロンプトに出し本文は要るときに読むこと、配置の文書の形と置き場、書き損じの扱いは変えない。

### 道具の使い方の文書は image に入れる

- このリポジトリは、image が入れている道具とこのリポジトリの道具について、どの配置でも同じ使い方を、コネクタの文書として持ち、sandbox の image に入れる。配置の設定が無くても、つねに一覧に載る。
- image の文書は、配置の値（ホスト・ワークスペース・token の環境変数の名前・宛先の一覧）を持たない。ホストは配置が登録するものなので、image の文書はホストを持たない。
- 配置の文書は、その配置だけのこと（ホスト、サロゲートを持つ環境変数、ワークスペースや宛先の一覧、その配置だけの決まり）を書く。

### 同じ名前の文書は 1 つのコネクタとして重ねる

- runner は、image の文書と配置の文書を名前で突き合わせ、1 つの名前を一覧の 1 項目にする。
- 両方にある名前は、配置の説明とホストを載せ、文書の場所を配置のもの、image のものの順に両方載せる。プロンプトは、両方あるときに食い違えば配置の文書が勝つ、という事実を伝える。
- image にだけある名前は、ホストを持たない項目として載る。プロンプトは、ホストの無い項目はこの配置に登録が無いことを伝える。
- 配置にだけある名前は、今までどおり載る。

### 共通の skill も image に入れ、オーナー・記憶の後に置く

- どの配置でも同じ skill（`self-portrait`・`goals`）は、このリポジトリが持ち、sandbox の image に入れる。runner は、オーナーの skill、記憶の `skills/` と並べて読む。
- 同じ名前のときは、オーナーの skill、記憶の skill、image の skill の順に勝つ。image の skill は既定であり、配置もエージェント自身も同じ名前で置き換えられる。
- image の skill の文は英語で書く（AGENTS.md「Prompts」）。記憶のファイルの形を決める見出しや印（`goals` の節の見出しなど）は、natsumi の記憶と同じに読めるよう、natsumi が書いてきた日本語のままにする（ADR-0006）。

### 姿の素材はアバターの置き場にまとめる

- アバターの姿の素材は、顔のアイコンと同じアバターのディレクトリに置く。このリポジトリの `assets/avatars/` を、backend だけでなく sandbox の image にも入れる。
- sandbox は、backend と同じ設定でアバターを選び、そのアバターの姿の素材を読む。配置がこのリポジトリに無いアバターを使うときは、アバターの置き場を 1 つ mount すれば、backend の顔も sandbox の姿もそこから取る。
- 配置が sandbox の決まった場所に姿の素材を置いているときは、それを選んだアバターより先に使う。今ある配置を壊さないためで、今ある配置がアバターの置き場から姿を取るようになったら、この場所を読むのをやめてよい。
- 配置が `sdctl` の params を自分で指していれば、それを変えない。

### 守る対象と、失敗したときの倒し方

- image の文書と skill は公開のリポジトリにあるので、配置の値も鍵の値もサロゲートの値も書かない。守る対象は ADR-0004 と同じく本物の鍵であり、本 ADR はそれを変えない。鍵の差し替えは、今までどおり Sentinel の設定だけで決まる。
- image の文書が書き損じていれば、ADR-0020 の書き損じの扱いと同じく一覧から外してログに書き、セッションは止めない。
- 選んだアバターに姿の素材が無ければ、決まった姿は無いものとして扱う。

### 本 ADR で決定しないこと

- image の中の置き場、runner の読み方、文書の front matter の形、sandbox にアバターを伝える設定の名前（委譲先: [Sentinel の設定と記録の仕様書](../sentinel-config.md) の「コネクタの文書」と [Pod の形の仕様書](../pod.md) の「volume」「姿の素材」）
- image に入れる文書と skill の個々の中身（委譲先: `packages/runner/image/` の文書と skill）
- モデルの API の文書を image に入れるか（委譲先: 配置のリポジトリ。宛先・provider の名前・共有の仕方がどれも配置ごとで、汎用にできる部分が残らなかった）
- 今ある配置の文書を、その配置だけのことに縮める時期（委譲先: 配置のリポジトリ）

## Consequences

- 配置の設定が無くても、エージェントは最初のセッションから、image の道具の使い方を知れる。公開のこのリポジトリだけで、道具の使い方と共通の skill と姿の素材がそろう。
- 道具の版を上げるときに、使い方の文書を同じ変更で直せる。配置ごとの写しを直して回らずに済む。
- 配置の文書は短くなる。一方で、今ある配置の文書は汎用と重なる中身を持ったままなので、縮めるまでは同じ使い方を 2 つの文書で読むことになる。食い違えば配置の方が勝つので壊れはしないが、縮めるまでは読む量が増える。
- ホストの無い項目は、配置が登録していなければ使えない道具の使い方も一覧に載せる。エージェントは、ホストの無いことから登録の無いことを知る必要がある。
- オーナーや記憶の skill が image の skill に勝つので、image の skill を直しても、同じ名前を置いている配置や記憶には届かない。
- sandbox の image に、アバターの絵のぶんの大きさが加わる。
- 姿の素材を置く古い場所は、今ある配置が移るまで読み続ける。

## Alternatives Considered

- **同じ名前なら配置の文書だけを載せる**: 今ある配置はそのまま動くが、配置の文書を縮めると、その名前の image の文書が隠れたまま、使い方が届かなくなる。縮めるには別の名前を付けるしかなく、名前で登録と文書を対にする ADR-0020 の形が崩れる。
- **image の文書を別の種類（道具の一覧）として、コネクタの一覧とは別に出す**: 名前が同じでも 2 か所に出て、どちらを読めばよいかが分からない。今ある配置では同じ中身が二重に出る。
- **道具の使い方を image の skill にする**: skill は手順を持つもので、ホストの登録と対にする決まりが無い（ADR-0020 の Alternatives Considered と同じ理由）。
- **image の skill をオーナーの skill より先に置く**: 今ある配置が置いている同じ名前の skill が使われなくなり、配置ごとの直しが効かなくなる。
- **姿の素材を今までどおり配置が写す**: 1 つのアバターの素材が 2 つのリポジトリに分かれたままで、公開のリポジトリだけでは姿で描けない。
