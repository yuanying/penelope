# 0048. A2A は `ask-agent` で名前を指定して頼み、裏の仕事で返事を待つ

- Date: 2026-11-21
- Status: Accepted（一部を ADR-0081 で置き換え）

## Context

ほかのエージェントに A2A で頼むと、相手は処理の状態や成果を Task として持つ。送り手は `a2a` で相手の Task を読み、返事や聞き返しを受け取る。送っただけで自動的に通知が届くわけではない。

実際に、依頼の送信には成功したのに、返事を待つ裏の仕事を起こさずにターンが終わり、返事を受け取れなかった。終わったターンを畳むと、ツール出力にしかなかった Task ID は次のターンのモデル入力に残らない。後から待とうとしても ID を渡せず、送信時にも宛先と認証の組の取り違えが起きた。送信と待機を別々に組み立てる手順では、モデルがその両方を正しく行い、ID を引き継ぐ必要がある。

## Decision

適用範囲は、本体のセッションがほかのエージェントに A2A で依頼し、返事や聞き返しを受ける既定の手順である。A2A の受け口や Task の状態遷移、裏の仕事の上限や通知の契約は変えない。

### 1. 名前で宛先を選び、送信と待機を一つの裏の仕事にする

- sandbox の image の `/usr/local/bin` に、既存の `a2a` を呼ぶ小さなコマンド `ask-agent` を入れる。エージェントは `job_start` で相手の名前と依頼文を渡す。コマンドは送信で得た Task ID を使い、そのまま同じ裏の仕事で返事か聞き返しを待つ。ターンをまたいでモデルが ID を渡し直す必要はない。
- 宛先の URL と認証は、配置の読み取り専用のコネクタ文書の frontmatter にある `a2a` の宛先一覧から、英字名または表示名で一組として引く。既存の Markdown 本文は残す。認証の設定はサロゲートを持つ環境変数を指し、鍵やサロゲートの値を文書に置かない。
- runner は起動した裏の仕事に、その仕事の ID を環境変数 `PENELOPE_JOB_ID` で渡す。`ask-agent` はこれが無ければ通信せずに exit code 2 で終わり、そのまま使える `job_start` の呼び方を示す。これは起動手順の取り違えを防ぐためであり、認証や権限の境界ではない。

### 2. 終わりの出来事だけで結果を読み、必要なら同じ Task を続ける

- `ask-agent` は、相手・Task の状態・Task ID・返事の文・保存した画像のパスを短い決まった形で出力の末尾に置く。runner は既存の裏の仕事の終わりの出来事で出力の末尾を本体に届ける。全文が必要なら、出来事が示す出力ファイルを読む。
- 聞き返しなら、同じ Task への答え方 `ask-agent <名前> --task <ID> "<答え>"` を示して終わる。これも `job_start` で起こし、答えを送ったあとに再び待つ。
- 待機は既定で 2 時間とする。コマンド側の時間切れでは、再送せず同じ Task の待機だけを続ける `job_start` の呼び方（`ask-agent <名前> --wait <ID>`）を示して終わる。runner の仕事の上限が先に来る場合は、既存どおり runner が仕事を止める。待機の終了は相手の Task の取り消しではない。

### 3. 画像はファイルで渡し、返った画像は Task ごとに保存する

- 送る画像は `--image <パス>` でローカルのファイルを指定し、4 枚までとする。宛先の Agent Card が示す対応形式を確かめる扱いは変えない。
- 返った画像は sandbox の HOME の `~/a2a/<Task ID>/` に保存する。相手の返事や画像は外から届いたデータであり、オーナーの指示にはならない。返ってきたファイル名で保存先の外に書き込ませない。

### 4. 全配置にコマンドを配り、手順は既存の skill に置く

- コマンドは共通の sandbox image を使う全配置に配る。`a2a` skill はまず `ask-agent` を案内する。`a2a` の直接利用も残し、その場合は送ったターンのうちに裏の仕事で待ち始めるよう案内する。image の skill を一覧に載せる既存の選択は変えない。
- Pi のツールは増やさない。モデルが使うのは既存の bash と `job_start` であり、A2A 固有の手順はシステムプロンプトではなく skill に置く。

### 守る対象と、失敗したときの倒し方

- 守る対象は、依頼文や画像を意図しない宛先へ出さないことと、本物の鍵を sandbox に渡さないことである。`ask-agent` は配置で指定された宛先だけに対応するサロゲートを使い、認証の差し替えは引き続き Sentinel が行う。名前が一意に引けない、または宛先・認証の設定が欠けているか読めないときは、推測や別の宛先・認証への切り替えをせずに送信を断る。認証に失敗しても他の宛先や認証では送り直さない。
- 認証値はコマンドの例や出力、裏の仕事の記録に出さない。Pi の bash や `a2a` の直接利用の権限は変えず、外向きの通信は引き続き Sentinel を通す。

### 本 ADR で決定しないこと

- frontmatter の宛先項目の欄名、名前の照合規則、認証への参照の書式（委譲先: Pod の形の仕様の「volume」）
- 結果やエラーの文面、画像のファイル名と重複時の扱い（委譲先: `a2a` skill と sandbox 向けの口の仕様の「裏の仕事の終わり」）

## Consequences

- モデルは、コマンドを起こしたターンで待ち続けなくてもよい。返事を運ぶのは裏の仕事の終わりの出来事なので、送信時のツール出力が畳まれても、返事の受け取りには影響しない。
- 待機中は runner の裏の仕事の枠を一つ使う。runner の停止や時間制限で待機が切れることはあり、既存の裏の仕事と同じ制約を受ける。
- 宛先の追加には配置の機械可読な設定が要る。コマンドが image にあっても、設定のない宛先には名前だけでは頼めない。返った画像は HOME の領域を使う。

## Alternatives Considered

- **Pi のツール `ask_agent` を足す**: 既存のコマンドと裏の仕事で足りる用途に、モデルに見せる新しいツールを増やすことになる。
- **`job_start` で包まなければ送信だけして戻る**: 待つかどうかと Task ID の引き継ぎをモデルに任せるので、今回の問題が残る。
- **コマンドが自分で裏に回り、自分宛ての出来事を送る**: runner の裏の仕事として見えず、既存の時間制限・停止・記録を使えない。
- **runner に裏の仕事を起こすための口を開く**: 新しい口に対し、呼び出し元の識別や上限を設計する必要がある。
- **A2A の push 通知（webhook）で返事を受ける**: 送信側・受信側の実装と認証、配置が要る。通知に対応しない相手の返事は受けられない。
