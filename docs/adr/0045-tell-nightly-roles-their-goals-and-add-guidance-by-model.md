# 0045. 夜のプロンプトは目的を伝え、印の付いたモデルだけに手順を足す

- Date: 2026-11-20
- Status: Accepted（一部を [ADR-0059 トピックには今わかっていることを残し、棚卸しの同順位では大きいものを先に読む](0059-keep-topics-current-and-review-large-topics-first.md) で置き換え）

## Context

振り返りの入力は、セッションが終わること、翌日が記憶から始まること、整理係が続くことを伝えるが、翌日の自分が何をできるようになるべきかは伝えない。整理係には記憶が見つかり最新であるという目的を伝える一方、夜の働き方にモデルごとの違いはない。

記憶について目的だけを示すと、何を残し、どう確かめるかをモデルに任せられる。一方、Anthropic の記憶の評価では、古いモデルに記憶を読むことと仮説を確かめることを明示してスコアが改善した例があり、新しいモデルは同じ手順を言わなくても行っていた。penelope で同じ効果が出ると仮定せず、共通の目的で足りないモデルだけを対象にする。

## Decision

### 1. 夜の各係に共通の事実と目的を渡す

振り返りのターンの入力と、照合係・整理係のシステムプロンプトでは、役目・環境・資料の所在に加え、その段の結果が何に役立つかを伝える。既定では、目的を果たすためのやり方はエージェントに任せる。根拠となる記録の所在と目的を伝えることは、記録に書かれた文を手順として渡すこととは異なる。

### 2. 共通の本文で足りないモデルだけに手順の層を足す

共通の本文を先に使い、特定のモデルだけで夜の振り返り・照合・整理が浅いと分かったときは、モデルカタログの該当エントリにオーナーが手で印を付けられるようにする。印のあるモデルにだけ、共通の本文に手順の層を加える。モデルごとの別の本文は持たない。印が無ければ共通の本文だけを使う。共通の本文で十分に働くと確かめられたモデルからは印を外す。

この例外は夜の振り返りの入力と、照合係・整理係のシステムプロンプトに限る。日中のターン、日中のシステムプロンプト、サブエージェントのプロンプト、ツールの説明には広げない。仕組みで守る線を手順の層に移さない。印は選ばれたモデルのプロンプトだけを変え、夜のモデルの選択には関与しない。

### 本 ADR で決定しないこと

- 共通の本文と手順の層の文面（委譲先: [runner のプロンプトのファイル](../../packages/runner/src/prompts.ts)）
- 印の名前、形式、読み込み方（委譲先: [モデル設定を扱う runner のコード](../../packages/runner/src/model-settings.ts) とモデルカタログの実装）
- 印を付ける具体的なモデル（委譲先: オーナーによるモデルカタログの運用）

## Consequences

- 何に役立つ記憶かを伝えつつ、すべてのモデルに手順を強制せずに済む。共通の本文の直しが、手順を必要とするモデルにも届く。
- モデルを更新したときは印の要否を見直す手間がかかる。印を付けたままにすると、不要になった手順が判断を狭め、入力も増える。反対に、印が無ければモデルによっては照合や整理が浅いままになる。
