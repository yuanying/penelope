# 0059. トピックには今わかっていることを残し、棚卸しの同順位では大きいものを先に読む

- Date: 2026-11-24
- Status: Accepted

## Context

日付が過ぎた予定・期限や、何をいつ確かめたかの日ごとの記録が、複数の夜を経てもトピックに残っていた。日中のセッションにはトピックと `diary/` の違いが十分に伝わらず、日次の整理係にも、過ぎた予定や期限をいつトピックから外すかが示されていなかった。

週の棚卸しは、一晩で本文を見直す分量に目安を設け、まだ対象に入っていないファイル、次いで最後に対象に入った日が古いファイルを選ぶ。同順位ではパス順だったため、記録が溜まって大きくなったトピックでも、パスによっては一巡の末尾まで本文を見直せなかった。

## Decision

### 1. 今の知識と日ごとの経緯を分ける

トピックは今わかっていることを置く場所とし、何をいつ確かめたかの日ごとの記録は `diary/` に置く。この区別を日中のセッションと夜の係に共通して伝える。現在の事実を裏づける時点と根拠は、トピックにも残す。

日次の整理と棚卸しの中身の見直しでは、トピックに溜まった日ごとの確認記録を `archive/` に要約し、トピックから外す。日付が過ぎた予定・期限は、オーナーの言葉や記録から片が付いたと分かる場合だけ、同じ扱いにする。日付が過ぎただけでは済んだと推測せず、片が付いたか分からない予定・期限はトピックに残す。先の予定や、日付を過ぎても効く情報（後日のリマインドなど）も残す。日記はそのまま残し、照合係の役目には移動や要約を加えない。

### 2. 棚卸しの同順位では大きいトピックを先に読む

本文を見直すトピックは、まだ対象に入っていないものを先に、次いで最後に棚卸しの対象に入った日が古いものから選ぶ。同じ日（まだ対象に入っていないもの同士を含む）では大きいものを先にし、大きさも同じならパス順にする。一晩の分量の目安や、最優先の 1 ファイルが目安を超えるときの単独選択は変えない。

### 本 ADR で決定しないこと

- プロンプトの文面（委譲先: [runner のプロンプト](../../packages/runner/src/prompts.ts)）
- 棚卸しの分量の目安と選択の実装（委譲先: [sandbox API の仕様書「セッションの切り替えの知らせ」](../sandbox-api.md#セッションの切り替えの知らせ) と runner）

## Consequences

- 今も意味のある情報と、過去の経緯をそれぞれ見つけやすくなる。一方、対応を確認できない予定・期限は溜まりうる。数週間の記憶の増え方を見て、そのような項目が無駄に溜まるなら、残し方を見直す。
- 同じ優先度なら、本文の大きいトピックを早く見直せる。小さいトピックが待つ場合はあるが、棚卸し対象に入った日による優先順位は維持する。ファイルの大きさは、内容が古いかどうかの判断には使わない。

## Alternatives Considered

- 日付だけで過ぎた予定・期限をトピックから外す案は採らない。対応を確認できていない項目まで、解決済みと取り違えて見つけにくくするためである。
