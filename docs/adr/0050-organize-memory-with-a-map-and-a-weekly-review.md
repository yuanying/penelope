# 0050. 夜は記憶の見取り図を渡し、棚卸しで中身と構成を分けて見直す

- Date: 2026-11-21
- Status: Accepted（一部を [ADR-0059 トピックには今わかっていることを残し、棚卸しの同順位では大きいものを先に読む](0059-keep-topics-current-and-review-large-topics-first.md) で置き換え）

## Context

夜は振り返り、照合係、整理係、新しいセッションの 4 段に分かれる。整理係に渡すのは、変わったパス、毎回読むファイルと記憶全体の大きさであり、他のページの構成、いつ書かれたり読まれたりしたか、古い要約をいつまとめるかは分からない。既に本番の 5 配置で記憶は 22〜741 KB の差があり、5 日で 49 ファイル・488 KB、`archive/` は 0 件という例もあった。全体の見取り図と、本文まで読む範囲を分ける必要がある。

毎回読む層には個々のファイルがプロンプトに入る上限があるが、層全体を小さく保つ目安はない。また、日ごとの経緯を残す `diary/` と、古くなった事実の要約を残す `archive/` は役目が違う。どちらも毎回読む層には入らないが、後者は古い要約が増え続けると経緯を探しにくくなる。

## Decision

### 1. 夜は日中の知識づくりを補う

振り返りと照合係と整理係の分担は維持する。runner は照合係と整理係に、`PURPOSE.md` を知識の基準として渡す。あわせて、`goals/` の長く続く目標の「なぜ」を、いま力を入れていることの手がかりとして渡す。「今の様子」と `today.md` は含めない。`PURPOSE.md` がない配置では、夜の係は従来の目的で動く。

照合係は原本を確かめ、誤りを直すだけでなく、目的に照らしてその日の書き漏らしを拾う。構成は触らず、直すことがなければ変更なしでよい。整理係は、必要な知識を見つけられ、現在の状態を答えられる構成にする。振り返りと整理係には、毎回読む層として、存在する `PURPOSE.md` を含む 4 ファイルの大きさを伝える。

### 2. 毎晩、全体の見取り図と毎回読む層の目安を渡す

runner は毎晩、整理係に記憶全体の見取り図を渡す。ファイルごとの大きさ、最後に変わった日、最後に夜の係が書いた日、見出しごとの行数とリンクのつながりを示す。本文を全て読む範囲を絞っても、見取り図は絞らない。

日中のセッションの記録から `/memory` を読んだり検索したりした記録を夜ごとに拾い、パスと日付だけを runner の状態に残す。見取り図に最終参照日と直近 30 日の参照回数を添える。検索語や記憶の本文は参照の集計に保存しない。参照がないことは不要の証拠ではないので、削除や `archive/` 行きの条件にしない。

毎回読む層の合計の大きさと目安を伝える。超えた夜は整理係の最初のターンの入力の先頭で、まず縮め、細部はトピックへ移してリンクを残すことを優先させる。超過は活動の記録に出す。個々のファイルをプロンプトに入れる上限はそのままとし、目安をコミット前の検査にしない。

### 3. 週の棚卸しだけ、整理係を 2 ターンにする

週 1 回の棚卸しでは、日次の整理に代えて、同じ整理係が次の 2 ターンを順に行う。それぞれ新しいセッションで行い、夜の段や棚卸し専用の係は増やさない。それ以外の夜は 1 ターンを維持する。

1. **中身**: 見取り図、本文を見直す範囲、その週の `diary/` の一覧を渡す。一度に読める大きさなら全体を対象にし、収まらなければ最後に夜の係が書いた日が古いものから、収まる分を対象にする。日をまたいで繰り返すことを日記から拾い、トピックへ書き起こす。トピックを現在の状態に更新し、古い事実の要約は `archive/` に移す。
2. **構成**: 中身のターンの後の全体の見取り図、`INDEX.md`、`PURPOSE.md` の答えられるべき問い、リンクのつながりを渡し、本文は必要なものだけ開く。最初に「目的に合わせた構成になっているか」を問う。統合・分割・移動・索引・リンクの見直しは例外ではなく、このターンに期待する仕事である。

### 4. 日記は残し、古い要約だけをまとめる

夜の整理で `diary/` は粗くせず、日ごとの経緯を残す。`archive/` は月単位で要約を持ち、3 か月で四半期に、1 年で年にまとめる。まとめる対象と行き先は runner が計画して整理係に渡す。本文の要約は整理係が行い、計画どおりかを検査してコミットを拒否する仕組みは置かない。

### 本 ADR で決定しないこと

- 毎回読む層の合計の目安と、棚卸しの 1 ターンで本文を読める大きさ（委譲先: 設定と実装）
- プロンプトの文面、見取り図の形式と参照の拾い方、archive の計画の形式（委譲先: runner の実装）
- 活動の記録の欄と表示（委譲先: UI 向けの API の仕様書「活動の記録」）
- セッションの記録と `/sources` の保存年数（委譲先: オーナーの運用と backend・runner の設定）

## Consequences

- 記憶が増えても、一晩で読む本文を限りながら全体を見渡せる。中身を読む仕事の後に空の文脈で構成を考えるため、構成の見直しを後回しにしない。一方、全文を一度に確認しないので、手が入るまで古い記述が残る。棚卸しでは別のセッションの分だけ時間とモデルへの入力も増える。
- 日記で経緯をたどれるが、日記が使う保存領域は増え続ける。要約の粒度を落とすのは `archive/` に限り、古い詳細は日記や git の履歴でたどる。
