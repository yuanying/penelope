# 0057. オーナーによる記憶の編集と復元は、backend が 1 ファイルずつ確定する

- Date: 2026-11-23
- Status: Accepted

## Context

記憶の画面では Git にコミットされた本文と履歴を読めるが、そこで誤記を直したり、過去の本文に戻したりはできない。backend はターンの終わりに作業ツリーをコミットする。画面で見た版と保存時点の版が異なる場合に加え、コミットされていないエージェントの書きかけが作業ツリーにある。夜の整理係はパスを移動することもある。

## Decision

### 1. 既存のファイルだけをオーナーが保存する

Git の `.git` に書くのは引き続き sandbox の外の backend とする。既存のオーナー認証を通った要求だけが保存できる。コミットの作者はログイン名ではなく配置の設定から取り、オーナーのメールが設定されていなければ保存しない。Git の出力や記憶の本文はログに残さない。

対象は、記憶の閲覧で本文を返せる既存の通常ファイル（Markdown・テキスト）に限る。`avatar/` の編集、ファイルの作成・削除、消えたファイルの復元は含めない。復元は選んだ過去の本文を現在のファイルに保存する操作であり、履歴自体を巻き戻さない。毎回読む層のファイルは、個々の本文がプロンプトに入る上限を超える保存を断る。層全体の目安は保存を断る条件にしない。エージェントの変更をターン末に検査せず確定する方針は変えない。

### 2. 対象のパスの食い違いを調べてから確定する

日中も夜も保存を受け付ける。対象の 1 ファイルについて、編集の起点と現在のコミット済みの版が一致し、作業ツリーにも未確定の差がないときだけ保存する。移動・削除も食い違いとして扱う。確定済みの変更はその差分を返し、未確定の差は存在だけを伝える。

判定・更新・コミットは、ターン末などのコミットと同じ待ち行列に並べる。保存したファイルだけをコミットし、ほかの書きかけは含めない。本文に変更がなければコミットしない。保存は出来事にせず、次のターンにも会話にも添えない。

### 本 ADR で決定しないこと

- API の書式、コミットの印、各上限の値（委譲先: References の UI・backend の仕様書）。

## Consequences

- オーナーは他のファイルの書きかけを待たず、現在の本文を直したり過去の本文に戻したりできる。変更は履歴にオーナー名義で残る。
- 同じファイルが変わった場合は保存をやり直す必要がある。ターンを止めずに保存できる代わりに、待ち行列の外で sandbox が行うファイル操作まではロックしない。
- 保存だけではエージェントは起動しない。すぐに読ませたい場合は、オーナーが会話で頼む。

## Alternatives Considered

- コミット済みの版だけを比較する案は、ターンや夜の途中にある作業ツリーの変更を上書きするため採らない。
- ターンが終わるまで編集を閉じる案は、対象と無関係な作業にも待たされるため採らない。
