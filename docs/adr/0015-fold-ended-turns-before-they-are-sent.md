# 0015. 終わったターンは、モデルに送る直前に機械的に畳み、セッションの記録は書き換えない

- Date: 2026-11-14
- Status: Accepted（Decision「地の文の無いターンにだけ、畳む前に一度だけ頼む」の、頼まないターンに ADR-0031 で 1 つ足した。その一覧を [ADR-0071 ツールを呼ばず地の文も無く終わったターンには、畳む前の頼みを送らない](0071-skip-the-fold-request-after-turns-without-tools.md) で一部置き換え）

## Context

ADR-0007 で、セッションは 1 本にし、夜に切り替えると決めた。日中の文脈があふれたときは Pi の compaction で続ける、とだけ決めており、それより手前で文脈を軽くする仕組みは無い。

ここで言うターンは、runner が出来事をまとめて Pi に 1 回渡してから、エージェントがツールを呼ばずに止まるまでである。途中で届いた出来事は steer か follow-up で同じターンに入る。ターンが終わると、backend が `/memory` をコミットする。

Pi は、モデルを呼ぶたびに、そのセッションのメッセージを全部送り直す。過去のターンの思考も、ツールの出力も、毎回送られる。エージェントは Pi の基本のツールで何でもする（ADR-0001・ADR-0011）ので、1 日の文脈の大半は、終わったターンの途中経過になる。natsumi の本番の 3 日分の session では、日中のターンの約 87% が途中経過（思考とツールの呼び出し・結果）で、届いた出来事と返事は 1 割あまりだった。1 日の文脈は 7〜8 万 tokens に達し、compaction が 1 日に 0〜2 回走っていた。compaction は、走るたびに prefix cache を全部外す。

natsumi はこれを、終わったターンを送る直前に畳み、ターンごとにサーバーが頼んだ一行のメモを残す形で解いた。ただしメモの頼みの文には、何をどう書くかの指図が入っている。penelope のプロンプトは事実と環境だけを伝え、やり方は任せる（ADR-0008）。

Pi には、モデルに送る直前にメッセージの列を差し替える `context` の拡張点と、ツールの呼び出しを実行の前に断る `tool_call` の拡張点がある。どちらも、セッションの記録には触れない。

ここで使う言葉は次のとおりである。

- **畳む**: 終わったターンを、モデルに送る分だけ短くすること。セッションの記録はそのまま残る。
- **地の文**: エージェントがターンの中で書いた文のうち、ツールの呼び出しでも思考でもないもの。オーナーには届かない（届くのは `reply` だけである）。
- **prefix cache**: provider が、前の呼び出しと先頭が同じ分の入力を読み直さずに済ませる仕組み。

## Decision

本 ADR は、ADR-0007 の Decision 項 3（文脈があふれたら compaction、足りなければ分け直す）を変えない。compaction の手前に、終わったターンを畳む仕組みを足す。適用範囲は、エージェントの日中のセッションである。整理係のセッションは 1 ターンで終わるので畳むものが無い。

### 終わったターンを、送る直前に畳む

- 畳むのは終わったターンだけである。今のターンは畳まない。文脈の途中をさかのぼって書き換えないので、prefix cache は直前に終わったターンの始まりまで保たれる。
- 畳み方は機械的な置き換えとし、モデルに要約させない。同じメッセージの列は、いつも同じに畳む。
- 畳んだ結果は、モデルに送る直前にだけ作る。セッションの記録は書き換えない。畳み込みを切れば、次の呼び出しから元の文脈に戻る。
- ターンの区切りは、セッションの記録だけから分かるようにする。runner が止まって立ち上がり直しても、同じように畳む。
- 畳んだターンに残すもの:
  - 届いた出来事。オーナーのメッセージも、要約と場所だけの出来事も、受け取ったときの形のままである。
  - `reply` の呼び出しと、その短い結果。
  - エージェントの地の文。
- 畳むもの:
  - 思考。
  - ほかのツールの結果。
  - ほかのツールの呼び出しは、コマンドやパスを 1 行に短く残す。1 つの呼び出しは 200 字までとし、出力は残さない。何を試したかは残るが、何が返ったかは残らない。
- 思考を外した呼び出しからは、思考と組になっていたことを示す識別子を外す。組の片方だけを送ると断る provider の API があるためである。
- compaction の要約と、ほかの種類のメッセージは、そのまま通す。
- 入り切りは runner の設定で決める。

### 畳まれることを、事実としてシステムプロンプトに書く

- 畳み込みが入っているとき、システムプロンプトに、終わったターンが畳まれること、何が残り何が消えるかを 1 文で書く。何を残すべきかの指図は書かない（ADR-0008）。

### 地の文の無いターンにだけ、畳む前に一度だけ頼む

- 地の文を 1 つも書かずに終わったターンでは、畳むと届いた出来事と呼び出しの行しか残らない。そのターンにだけ、同じセッションに続けて、短い頼みを 1 回送る。頼みは、これから畳まれることを伝え、残したいことがあれば書けると伝えるだけで、何を書くかは指図しない。
- 頼みへの答えは地の文として残り、頼みの文そのものは畳む。
- 頼みに答える間は、ツールを実行しない。ツールの定義は外さない（外すと prefix が動く）。呼び出しは実行の前に断り、答えは 1 回の呼び出しで終える。オーナーにも外にも何も出ない。
- 頼みは、そのターンの一部とする。頼みの間に届いた出来事は、次のターンで扱う。
- 夜の振り返りのターン（直後にセッションが替わる）、整理係のターン、失敗したターンには頼まない。畳み込みが切られているときも頼まない。
  - 2026-11-16 追記: ADR-0031 で、heartbeat の出来事だけで始まり、ツールを 1 つも呼ばずに終わったターンにも頼まないことにした。
  - 2026-11-27 追記: [ADR-0071](0071-skip-the-fold-request-after-turns-without-tools.md) で、受信元を問わず、ツールを 1 つも呼ばず地の文も無く終わったターンには頼まないことにした。

### ターンごとに、畳み込みの働きを runner のログに残す

- ターンごとに、そのターンの文脈で畳んだターンの数、頼んだかどうか、compaction が走った回数を、runner のログに 1 行で残す。本文は書かない。
- sandbox 向けの口の途中経過の契約は変えない。
- 畳み込みで足りないと分かったときは、natsumi と同じ、ターンごとの一行メモに替えることを考える。その判断の材料が、このログである。

### 本 ADR で決定しないこと

- システムプロンプトの 1 文と頼みの文の文面（委譲先: プロンプトのファイル `packages/runner/src/prompts.ts`。ADR-0008 の方針に従う）
- 1 行に残す呼び出しの書き方、ターンの区切りの記録の形、設定の名前と既定（委譲先: runner のコード `packages/runner/src/fold.ts` と `packages/runner/src/config.ts`）
- ログに残した数をどう集めて比べるか（委譲先: 配置の運用。最初は runner のログを読む）
- compaction の設定（委譲先: ADR-0007 の「本 ADR で決定しないこと」）

## Consequences

- 1 日の文脈は、届いた出来事・返事・地の文・呼び出しの行に収まり、compaction が起きにくくなる見込みである。compaction が prefix cache を全部外す回数が減る。
- ターンが終わるたびに、prefix cache は直前のターンの始まりまで戻る。1 ターンの伸びは、そのターンの残す分だけになる。
- 畳むのはターンが終わってからなので、1 ターンで何度も呼ぶ重いターンは、そのターンの間は途中経過を全部積む。
- 終わったターンのツールの出力は見えなくなる。前に調べたことが要れば、調べ直すか、地の文や `/memory` に書いておいたものを読むことになる。何を残すかはエージェントに任せる。
- 地の文の無いターンでは、モデルの呼び出しが 1 回増える。
- 夜の振り返りは、畳んだ文脈で行う。1 日の途中経過は見えず、地の文・返事・呼び出しの行と `/memory`・`/sources` が手がかりになる。
- セッションの記録は畳まないので、記録と UI の写し（途中経過）には全部が残る。モデルに見えていたものと記録が一致しないことを受け入れる。
- 畳み込みが足りているかは、runner のログの数だけで判断することになる。迷いの指標（読み直し、ツールのエラー）は数えない。

## Alternatives Considered

- **地の文の無いターンは畳まない**: オーナーは、ほとんどのターンが畳まれずに残りそうだとして採らなかった。ツールを使って `reply` で答えるだけのターンは、地の文を書かないことが多い。
- **natsumi と同じく、毎ターン指図つきの一行メモを頼む**: 毎ターン呼び出しが 1 回増え、頼みの文が何を書くかを指図する。ADR-0008 の方針に合わない。
- **畳まずに compaction だけで続ける**: ADR-0007 のままの形。途中経過が文脈を埋め、compaction のたびに prefix cache を全部失う。
- **モデルに畳んだ中身を要約させる**: 毎ターン要約の呼び出しが要り、同じ列が同じに畳まれる保証が無い。
- **セッションの記録そのものを書き換える**: 畳み込みを切って元に戻せず、畳む前の記録も失う。
