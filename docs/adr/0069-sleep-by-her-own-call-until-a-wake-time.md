# 0069. エージェントは `sleep` で自分で眠り、起きる時刻まで出来事を受け取らない

- Date: 2026-11-27
- Status: Accepted

## Context

本体のセッションは、夜の切り替えで新しくなる。切り替えは、振り返り、照合係、整理係、新しいセッションの 4 段である。合図は、backend が設定の時刻に待ち行列へ入れる制御の出来事で、runner がそれを受けて 4 段を回す。

時刻に結び付いた設定は 3 つある。夜の切り替えの時刻、起きている時間、週の棚卸しの曜日である。起きている時間の外では、backend は `batch` の出来事を朝まで渡さず、heartbeat も入れない。`now` の出来事は起きている時間の外でも渡すので、夜中にもターンは回る。活動の記録の「逃した夜」は、切り替えの時刻の予定と記録を照らして決めている。

切り替えの時刻は、その日の様子と関係なく来る。本番の配置では、日中のターンは 1 配置あたり 40〜88 と開きがあった。オーナーは、エージェントが眠気と時刻を自分で見て、寝る時刻と起きる時刻を自分で決める形を求めた。あわせて、寝ている間は何も届かず、起きるのは自分で決めた起きる時刻だけ、と決めた。寝ている・起きているの正を、エージェントの判断 1 つにするためである。

runner は、制御の出来事をターンに割り込ませない。制御の出来事と、その後に届いた出来事は、今のターンが終わってから順に扱う。

ここで使う言葉は次のとおりである。

- **眠り**: 夜の切り替えの 4 段と、その後、起きる時刻まで出来事を受け取らない間を合わせたもの。
- **起きる時刻**: 眠るときにエージェントが決める、眠りが終わる時刻。
- **寝つく間**: 眠りを求めてから、4 段が済むまでの間。
- **安全網**: 眠気が限界を超えたときに、backend がエージェントを寝かせる仕組み。

## Decision

適用範囲は本体のセッションである。4 段の構成と段ごとの失敗の扱い（ADR-0044 の Decision 項 1（夜の切り替えを 4 段にする））、棚卸しの中身（ADR-0050 の Decision 項 3（週の棚卸しだけ、整理係を 2 ターンにする））、照合と整理の基準（ADR-0051 の Decision）は変えない。サブエージェントと裏の仕事は、眠りの間も今までどおり動く（ADR-0022 の Decision 項 4（サブエージェントの寿命は、本体が閉じるまで）、ADR-0030 の Decision 項 4（夜の切り替えと、runner の立ち上がり直し））。

### 1. 寝るのはエージェントが決める

- エージェントは、起きる時刻を引数に取るツール `sleep` で眠る。`sleep` は、オーナーへの返事のツールと同じく、backend に直接届く。渡すのは本体のセッションだけである。
- 設定の時刻に夜の切り替えを始めることは、やめる。
- backend は、眠りを求められたら、今の夜の切り替えと同じ制御の出来事を待ち行列に入れる。runner は、`sleep` を呼んだターンが終わってから 4 段を回す。runner の順番は変えない。
- `sleep` は「この時刻まで眠る」という望みを置く操作である。寝つく間にもう一度呼ばれたら、起きる時刻を置き直すだけで、切り替えを増やさない。
- 起きる時刻は、設定の最長の睡眠時間までに丸める。丸めたときは、ツールの結果でそれを返す。
- エージェントの本質につながるもの（眠る、気分）はツールにし、外のサービスにつながるものは CLI にする。

### 2. 眠りの状態は 3 つで、1 つの記録から引く

- 状態は「起きている」「寝つく間」「寝ている」の 3 つである。
- backend は、眠りごとに 1 つの記録（求めた時刻、求めたのがエージェントか安全網か、起きる時刻、4 段が済んだ時刻、起きた時刻）を永続に持ち、状態をそこから引く。backend が立ち上がり直しても、記録と今の時刻から同じ状態になる。
- 「起きている時間」の設定は、やめる。`batch` を溜めるか、heartbeat を入れるかは、この状態で決める。

### 3. 起きていない間は、出来事を渡さない

- 寝つく間と寝ている間、backend は、その眠りの制御の出来事のほかは runner に渡さない。`now` の出来事も渡さない。
- 出来事は捨てない。今までどおり待ち行列と `/sources` に入り、起きたときに渡る。
- 眠りを求める前に runner に渡っていた出来事は、切り替えの前にターンになる。
- 起きていない間は heartbeat を入れない。
- 裏の仕事とサブエージェントの終わりの知らせも出来事なので、起きたときに届く。A2A の Task の期限（ADR-0018 の Decision 項 3（上限と期限で、Task が開いたまま積もらないようにする））は、寝ている間も数える。

### 4. 起きるのは、起きる時刻だけ

- 起きる時刻に、backend が「起きた」ことを知らせる `now` の出来事を 1 件入れ、溜まった出来事と一緒に渡す。起きたとき専用の渡し方は作らない。
- この出来事には、heartbeat と同じもの（残っている仕事と、receivers のプラグインが預けた様子）を載せる。heartbeat を設定していない配置でも、起きた直後のターンが 1 つある。
- 寝ている間にエージェントを起こす手段は持たない。
- 起きる時刻を過ぎたら、必ず起きる。backend が止まっていて過ぎたときは、立ち上がったところで起きる。4 段が済む前に過ぎたときも、その時刻に出来事を渡し始める。済んでいない切り替えは、今までどおり制御の出来事の渡し直しでやり直す。

### 5. 眠気が限界を超えたら、backend が寝かせる

- 眠気（[ADR-0068](0068-sleepiness-as-one-value-with-its-facts.md)）が設定の限界を超えたら、backend がエージェントの代わりに眠りを求める。入口は `sleep` と同じ 1 つである。
- このときの起きる時刻は、配置の既定の睡眠時間で決める。
- 限界は、振り返りのターンが収まる余裕を残して決める。
- 安全網は状態から決める。backend が立ち上がり直した後も、限界を超えていれば働く。

### 6. 週の棚卸しは、前に成功した棚卸しの日付から 7 日以上後の最初の眠りで行う

- 棚卸しを曜日に結び付けない。前に整理係が完了した棚卸しと今回の眠りについて、それぞれ眠りを求めた配置の時間帯での日付を比べる。日付の差が 7 日以上なら棚卸しにする。
- 整理係の完了時刻から 7×24 時間を数えるのではない。毎日同じ時刻に眠っても 7 日おきとなり、棚卸しで読む日記の 7 日分と合う。
- 棚卸しが失敗した眠りは、前の棚卸しに数えない。次の眠りがもう一度棚卸しになる。

### 7. 眠れなかった眠りを、失敗に数える

- 活動の記録の「逃した夜」を、「眠りを求めたのに、決めた時間たっても切り替えの知らせが来ない眠り」に置き換える。まだ見ていない失敗にも、これを数える。
- 求めは制御の出来事として待ち行列に残るので、backend が止まっていた間の分も、後から分かる。

### 8. システムプロンプトには、自分の様子がどう働くかを事実として書く

- システムプロンプトに書くものの一覧（ADR-0008 の Decision（事実と環境を伝え、やり方はエージェントに任せる））に、「自分の様子（眠り、眠気、気分）がどう働くか」を足す。
- 眠りについて書くのは、眠ると何が起きるか、`sleep` で眠れること、寝ている間は何も届かないこと、眠気が限界を超えると寝かされることである。
- いつ寝るか、何時に起きるかは書かない。要るものは、オーナーかエージェントが記憶に書く。事実だけを伝え、やり方は任せる方針は変えない。

### 版を上げるときに守ること

- この決定を入れた版に上げた直後は、「起きている」から始める。やめた設定（夜の切り替えの時刻、起きている時間、棚卸しの曜日）が配置に残っていても、backend はそれで動きを変えない。

### 本 ADR で決定しないこと

- 眠気の限界、既定の睡眠時間、最長の睡眠時間、眠れなかったとするまでの時間（委譲先: [backend の仕様書](../backend.md) の「設定」。眠りを実装する作業単位で足す）
- `sleep` の引数と結果の形、制御の出来事と「起きた」出来事の中身（委譲先: [sandbox 向けの口の仕様書](../sandbox-api.md) と [出来事の仕様書](../events.md)）
- 活動の記録と状態の画面での見せ方（委譲先: [UI 向けの API の仕様書](../ui-api.md) と [docs/design](../design/README.md)）
- オーナーが、寝ているエージェントを起こす入口（委譲先: 要るとなったときの新しい ADR）
- システムプロンプトの文面（委譲先: プロンプトのファイル `packages/runner/src/prompts.ts`）

## Consequences

- 寝る時刻が、その日のコンテキストと時間に合う。文脈があふれる前に寝られる。
- `batch`、heartbeat、棚卸し、眠れなかった失敗が、1 つの眠りの記録から決まる。時刻の設定が 3 つ減る。
- 夜中のターンが無くなる。新しいセッションは、起きる時刻まで空のままである。
- 一方で、寝ている間は、オーナーの発言も、`now` にした警報も、A2A の依頼も届かない。起きる時刻まで待つ。待つ長さの上限は、最長の睡眠時間である。
- A2A の依頼は Task として受けるが、エージェントは起きるまで知らない。寝ている間に期限が来た Task は失敗になり、開いた Task が送り手ごとの上限に達すれば、新しい依頼は断られる。
- `sleep` を呼んだ後に届いた出来事（オーナーの「おやすみ」への返事など）は、起きるまで届かない。
- 起きた直後のターンに、寝ている間の出来事がまとめて入る。
- エージェントが寝ることを覚えるまでは、安全網が床になる。安全網だけで回ると、眠る時刻は日ごとにずれていく。
- 眠る時刻が配置ごと、日ごとにばらつく。眠りのたびに 4 段のモデルの利用が要り、1 日に 2 回以上眠ることもできる。
- backend が止まっていて切り替えの時刻を過ぎた、という見え方は無くなる。backend が止まっている間は、眠りを求めること自体が起きない。

## Alternatives Considered

- **設定の時刻の切り替えを残し、`sleep` はそれを早める手段にする**: 入口が 2 つになり、起きている時間の設定も残る。寝ている・起きているの正が、設定とエージェントの 2 つに分かれる。
- **寝ている間も `now` の出来事は渡す（今の振る舞い）**: 夜中のターンが新しいセッションに積もる。眠りがいつ破られるかを、エージェントが決められない。
- **`now` で起こされたら、起きたことにする**: もう一度寝るたびに 4 段が回る。照合係と整理係は記憶を書き換えるので、夜中の 1 通ごとに回すものではない。
- **起きる時刻を持たず、次の出来事で起きる**: 起きるのがエージェントの決定でなくなる。出来事が無い日は起きない。
