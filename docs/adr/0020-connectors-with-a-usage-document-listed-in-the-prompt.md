# 0020. コネクタは Sentinel の登録と使い方の文書の組にし、文書の一覧をシステムプロンプトに出す

- Date: 2026-11-14
- Status: Accepted（Decision「中身は配置が持つ」の、このリポジトリが文書の中身を持たない点は ADR-0035 で置き換え）

## Context

Sentinel は、配置が設定に書いたホストの登録について、sandbox が持つサロゲートを本物の鍵に差し替える（ADR-0004 の Decision「鍵は Sentinel が持つ」）。サロゲートは、配置が sandbox の環境変数や道具の設定ファイルに置く。どのホストが登録されているか、どのサロゲートがどの環境変数にあるか、そのホストをどの道具で使うかは、配置ごとに違う。

いまのエージェントには、これを知る道が無い。

- システムプロンプトは事実と環境だけを伝える（ADR-0008 の Decision「事実と環境を伝え、やり方はエージェントに任せる」）。個別のホストや環境変数は配置の値なので、このリポジトリのプロンプトには書けない。このリポジトリは公開なので、配置の値そのものもここには書かない。
- 記憶はゼロから始めることがある。記憶に使い方を書いておく形では、新しいインスタンスが最初に困る。
- 配置が sandbox に説明のファイルを置いても、システムプロンプトがそれを指さなければ、エージェントは見つけられない。

Muse（Meta の AI エージェント）は、組み込みのコネクタごとに、エージェントへの使い方の指示（SKILL）を書いて持たせている。

skill は、名前・説明・場所だけがシステムプロンプトの一覧に載り、本文はエージェントが要るときに読む形である。オーナーの skill はこの形で読み取りの場所から渡している。

ADR-0003 は、1 つのホストに特化した判定や処理を Sentinel に差し込むプラグインを「コネクタ」と呼んでいる。本 ADR では、その言葉を広げる。

## Decision

### コネクタは登録と文書の組

- **コネクタ**は、Sentinel のホストの登録（宛先と鍵の差し替え）と、その使い方の文書 1 つの組である。1 つのコネクタは、1 つ以上のホストの登録を含む（例: API のホストと git のホスト）。
- ADR-0003 のコネクタ（判定や処理のプラグイン）は、コネクタのうち Sentinel に差し込む部分である。プラグインを持たないコネクタもある。
- 文書には、サロゲートを持つ環境変数や設定ファイル、使う道具、注意を書く。鍵の値も、サロゲートの値も書かない。

### 文書は決まった場所に、決まった形で置く

- 配置は、sandbox の決まったディレクトリに、コネクタごとに文書を 1 つ置く。sandbox からは読み取りだけにする。
- 文書の先頭に、名前・説明・使うホストの登録の名前を機械が読める形で書く。本文は自由な Markdown である。
- ディレクトリ・ファイルの名前と先頭の形は、このリポジトリの仕様書が決める。

### runner が一覧にしてシステムプロンプトに出す

- runner は、新しいセッションを始めるたびにディレクトリを読み、コネクタの名前・説明・ホスト・文書の場所の一覧をシステムプロンプトに出す。本文は出さない。エージェントが要るときに読む。
- プロンプトの文は、コネクタが何で、文書がどこにあるかという事実だけにする。これは、外向きが Sentinel を通るという「どこにいるか」の事実の続きである（ADR-0008 の Decision「事実と環境を伝え、やり方はエージェントに任せる」）。
- 配置がディレクトリを設定しなければ、または読めるコネクタが 1 つも無ければ、一覧の節そのものを出さない。
- 先頭が読めない、または欠けている文書は一覧から外し、runner のログにファイルと理由を書く。ほかの文書は一覧に載せる。1 つの書き損じでセッションを止めない。
- 夜の整理係のプロンプトには出さない。整理係は記憶を扱い、外のサービスを使わないためである。

### 中身は配置が持つ

- このリポジトリが持つのは、規則（置き場所・ファイルの形・設定）と、それを読む runner だけである。
  - 2026-11-17 追記: ADR-0035 で置き換え。どの配置でも同じ道具の使い方の文書は、このリポジトリが持って sandbox の image に入れ、配置の文書は同じ名前で重ねる。
- 文書の中身は、配置のリポジトリが Sentinel の設定の隣に持つ。登録と文書が対応していること（文書のホストが登録にあり、鍵を差し替える登録にはどれかの文書があること）は、配置のリポジトリが確かめる。

### 守る対象と、失敗したときの倒し方

- 文書は sandbox から読めるので、鍵の値もサロゲートの値も書かない。守る対象は ADR-0004 と同じく本物の鍵であり、本 ADR はそれを変えない。
- 文書は sandbox から書き換えられない。エージェントが自分のメモを足すのは記憶の側である。
- 文書が無い、または欠けていても、鍵の差し替えは Sentinel の設定だけで決まり、変わらない。困るのは、エージェントが使い方を知らないことだけである。

### 本 ADR で決定しないこと

- ディレクトリの名前、runner の設定の名前、先頭の形（委譲先: [Sentinel の設定と記録の仕様書](../sentinel-config.md) の「コネクタの文書」と [Pod の形の仕様書](../pod.md)）
- 個別のコネクタの文書の中身と、登録との対応の確かめ方（委譲先: 配置のリポジトリ）
- コネクタのプラグインの差し込み口の形（委譲先: ADR-0003 の「本 ADR で決定しないこと」に挙げた、既定を ask に切り替えるときの ADR）

## Consequences

- エージェントは、記憶が空でも、どのホストで鍵が差し替わり、どの環境変数を使えばよいかを最初のセッションから知れる。
- 配置の値は配置のリポジトリに閉じたまま、エージェントに届く。
- 登録と文書を同じ場所で一緒に直せるので、片方だけが古くなりにくい。
- 一方で、一覧のぶんシステムプロンプトが長くなる。本文は載せないので、コネクタ 1 つにつき数行である。
- 文書の中身の正しさは、このリポジトリのテストでは確かめられない。配置のリポジトリの確かめに頼る。
- 「コネクタ」が、プラグインだけでなく登録と文書を含む組を指すようになる。Sentinel の設定の欄の `connector` は、引き続きプラグインの名前を指す。

## Alternatives Considered

- **使い方をオーナーの skill として渡す**: 形は同じだが、skill は手順を持つものであり、登録と対にする決まりが無い。登録と文書の対応を確かめる単位が作れない。
- **使い方を記憶の `always.md` に書く**: 記憶がゼロから始まると届かない。配置の値を記憶に写すことにもなる。
- **配置が置いた 1 つの説明のファイルをプロンプトが指す**: 1 つのファイルに全部のサービスが集まり、どの登録に対応するかが分からない。
