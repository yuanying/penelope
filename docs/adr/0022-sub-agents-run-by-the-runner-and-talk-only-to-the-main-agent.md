# 0022. サブエージェントは runner が非同期に回し、本体とだけツールと自分宛ての出来事でやりとりする

- Date: 2026-11-15
- Status: Accepted（一部を [ADR-0055](0055-show-unfinished-work-in-heartbeats.md) で置き換え）

## Context

エージェントのセッションは 1 本で、夜に切り替える（ADR-0007）。調べもの・リポジトリの修正・長い待ちのある作業も、いまはすべてこの 1 本のセッションのターンの中で行う。その間に届いたオーナーのメッセージは、ターンの途中に steer で入るが、エージェントは手元の作業を抱えたまま答えることになる。作業の途中経過はすべて本体の文脈に積まれ、終わったターンを畳んでも（ADR-0015）、今のターンの分は畳まれない。作業を並べることもできない。

最初の版の設計は、サブエージェントを後から足せるように 2 つの口を空けてある。sandbox 向けの口のすべての要求はエージェントの ID の欄 `agent` を持ち（本体は `main`）、sandbox から自分宛ての出来事を入れる口 `POST /v1/self-events` がある。backend は、`agent` が `main` でない `GET /v1/events` を断っている。

前提になる事実は次のとおりである。

- Pi は sandbox の中で runner が SDK で回している（ADR-0001）。Pi の SDK は、作業の場所（cwd）とセッションの記録のファイルを指定してセッションを作れ、記録のファイルから同じセッションを開き直せる。1 つのプロセスで複数のセッションを持てる。
- sandbox の中のプロセスはすべて同じ UID で動き、同じサロゲートを持つ（ADR-0004、ADR-0011）。Sentinel の記録からは、どのプロセスの通信かを見分けられない。
- 出来事の中身は backend が `/sources/<source>/<stream>/` に追記し、ターンには要約と場所だけが入る（ADR-0013）。`/sources` を書くのは backend だけである。
- `/memory` は、ターンの終わりに backend がコミットする（ADR-0006）。
- システムプロンプトは事実と環境だけを伝える（ADR-0008）。skill と、システムプロンプトの後ろに足す記憶のファイルは、エージェントが自分で書き換えられる。

ここで使う言葉は次のとおりである。

- **本体**: エージェントの 1 本のセッション。`agent` は `main`。
- **サブエージェント**: 本体が起こし、runner が回す、本体とは別の Pi のセッション。外のエージェント（A2A の相手）とは別のものである。
- **頼み**: 本体がサブエージェントに渡す言葉。起こすときの最初の頼みと、止まったサブエージェントに送る続きがある。
- **地の文**: ADR-0015 と同じく、ターンの中で書いた文のうち、ツールの呼び出しでも思考でもないもの。

## Decision

適用範囲は、本体が起こすサブエージェントと、そのサブエージェントと本体の間のやりとりである。本体のセッション・夜の切り替え・出来事の列の決定（ADR-0002・ADR-0007・ADR-0013）は変えない。

### サブエージェントは runner が非同期に回す

- サブエージェントは、runner が Pi の SDK で回す別のセッションである。本体と同じ sandbox・同じユーザー・同じ道具で動く。
- 本体がサブエージェントを起こすと、起こすツールはすぐ返る。サブエージェントは裏で走り、止まったら本体に知らせる。本体はその間も出来事に答えられ、サブエージェントをいくつも並べられる。
- 同時に走るサブエージェントの数に上限を置かない。sandbox の資源の上限を超えたときは、sandbox の中のプロセスが OOM で止まる。資源の上限と見方は、オーナーがエージェントの記憶に教える。

### サブエージェントは本体とだけ話す

- サブエージェントの言葉が届く先は本体だけである。オーナーへの返事（`reply`）、A2A の Task への返事（`reply_to_agent`）、予約は本体の道具のままで、サブエージェントには渡さない。オーナーから見た相手は、いつも本体 1 人である。
- サブエージェントは Pi の基本のツールと shell を持つ。外のエージェントへの A2A の CLI は shell の道具なので、サブエージェントも使える。
- これは道具を渡さないことによる線であり、仕組みで止める線ではない。サブエージェントも本体と同じサロゲートを持つので、shell から sandbox 向けの口を直に呼べる。backend は、`agent` が `main` でない返事・A2A の返事・予約を `400` で断る。これは取り違えを防ぐためで、守りではない（`agent` は sandbox の中の名乗りである）。

### 往復は「止まったサブエージェントに続きを送る」だけ

- サブエージェントは、1 回の実行（頼みを受けてから、ツールを呼ばずに止まるまで）の最後の地の文を本体に返して止まる。それが結果か問いかは、地の文が言う。runner は両者を見分けない。
- 本体は、止まったサブエージェントに続きを送れる。サブエージェントは同じセッションの文脈のまま続ける。
- 走っているサブエージェントには割り込まない。続きを送れるのは止まって待っているサブエージェントだけである。方向を変えたいときは、閉じて起こし直す。
- サブエージェントの状態は次の 3 つである。
  - **走っている**（running）: 頼みを受けて実行の最中。
  - **止まって待っている**（waiting）: 地の文を本体に返して止まり、続きか閉じられるのを待っている。
  - **閉じた**（closed）: 本体が閉じた。もう続きは送れない。
- 実行が失敗したとき（モデルの API が答えないなど）も、サブエージェントは止まって待っている状態になり、失敗したことを本体に知らせる。続きを送れば、同じ文脈でやり直す。

### サブエージェントの寿命は、本体が閉じるまで

[ADR-0055 残っている仕事は heartbeat の出来事にだけ載せる](0055-show-unfinished-work-in-heartbeats.md) で、本体への heartbeat に限り、開いたままのサブエージェントの状態とその状態になった時刻を入力に載せる。寿命や既存の道具は変えない。

- サブエージェントは、本体が閉じるまで残る。夜の切り替えもまたぐ。夜の切り替えのときに走っているサブエージェントは、走らせたまま置く。結果は、翌日の本体に出来事として届く。
- 翌日の本体は、一覧のツールで前の日のサブエージェントを知る。runner がサブエージェントの一覧をターンの入力やシステムプロンプトに差し込むことはしない。閉じ忘れは、エージェントが夜の振り返りで一覧を見て片付ける。
- runner は、サブエージェントごとの名前・状態・目的・作業の場所・役割と、セッションの記録の場所を、HOME の永続する場所に残す。runner が止まって立ち上がり直したら、閉じていないサブエージェントをそこから戻す。走っていたサブエージェントは止まって待っている状態にし、中断したことを本体に知らせる。続きを送れば、セッションの記録から再開する。
- 閉じたサブエージェントの記録とセッションの記録は消さない。

### サブエージェントを扱うのは、本体だけに渡すツール

- runner は、本体のセッションにだけ、次の 4 つの Pi のツールを渡す。サブエージェントには渡さないので、サブエージェントがサブエージェントを起こすことは無い。

| ツール | 中身 |
| --- | --- |
| `subagent_start` | サブエージェントを起こす。名前・目的・最初の頼みと、任意の役割・作業の場所を取る。同じ名前のサブエージェントがいればエラー |
| `subagent_send` | 止まって待っているサブエージェントに、名前を指して続きの言葉を送る。いない名前・走っているサブエージェントはエラー |
| `subagent_list` | 引数を取らない。閉じていないサブエージェントの名前・状態・目的・作業の場所を返す |
| `subagent_close` | 名前を指してサブエージェントを閉じる。走っていれば、その実行を取り消してから閉じる |

- 名前は本体が付ける。サブエージェントの名前は `/sources` の場所・作業の場所・sandbox 向けの口の `agent` に使うので、その場所に使える文字だけからなり、`main` ではなく、閉じたサブエージェントも含めて前のサブエージェントの名前と重ならないものに限る。形は sandbox 向けの口の仕様書が決める。
- ツールの名前は `subagent_*` で揃え、外のエージェント（A2A の相手。`reply_to_agent`、`source` が `a2a` の出来事）と言葉を分ける。
- 起こす操作と続きを送る操作は、別のツールにする。1 つにまとめると、起こすときにだけ効く引数（目的・役割・作業の場所）を続きのときにどう扱うかの決まりが要るためである。
- 目的は、一覧と Web UI に出す一言である。翌日の本体が、そのサブエージェントが何のためにいるかを知る手がかりになる。

### 本体からサブエージェントへは、ツールで runner の中を直接

- `subagent_start` の最初の頼みと `subagent_send` の続きは、runner がそのサブエージェントのセッションにそのまま渡す。backend を通らない。
- backend はサブエージェントの出来事の列を持たない。`agent` が `main` でない `GET /v1/events` は、これまでどおり断る。

### サブエージェントから本体へは、自分宛ての出来事

- サブエージェントが止まるたびに、runner が `POST /v1/self-events` で本体宛ての出来事を入れる。理由は 3 つある: 止まった（結果か問い）、失敗した、中断した。
- 出来事は、`source` が `self`、`stream` がサブエージェントの名前である。`payload` に最後の地の文の全文・理由・目的を入れ、`summary` に地の文の先頭を入れる。`id` はサブエージェントの名前と、そのサブエージェントが止まった回の番号からなる。runner が同じ知らせを送り直しても、backend が `id` で重複を落とす。
- 中身は ADR-0013 のとおり backend が `/sources/self/<サブエージェントの名前>/` に追記し、本体のターンには要約と場所が入る。サブエージェントの結果のための新しい置き場は作らない。
- 渡す時は、backend の中の受信元 `self` の設定（ADR-0013 の Decision 項 3（渡す時は受信元の側が出来事ごとに決める））に従う。

### 作業の場所

- `subagent_start` は任意の作業の場所（cwd）を取る。省けば、runner が HOME の下にサブエージェントの名前の空のディレクトリを作り、そこを作業の場所にする。
- リポジトリの仕事で worktree を使うときは、本体が git で worktree を作り、その場所を渡す。runner は git を知らない。枝・base・いつ消すかは本体が決める。
- サブエージェントを閉じても、作業の場所は消さない。

### サブエージェントの途中経過とターンの終わり

- runner は、サブエージェントの途中経過を、`agent` をサブエージェントの名前にして sandbox 向けの口へ送る。形は本体と同じである。
- サブエージェントの 1 回の実行の終わりにも、runner は `agent` をサブエージェントの名前にしてターンの終わりを送る。backend は、本体のときと同じく `/memory` の作業ツリーの変わったものをコミットする。サブエージェントが `/memory` に書いたものを、本体の次のターンを待たずに履歴に残すためである。そのとき本体のターンの途中の変更も一緒にコミットされることを受け入れる（コミットは作業ツリーの写しであり、壊れはしない）。
- サブエージェントのセッションには、終わったターンの畳み込み（ADR-0015）を入れない。サブエージェントの続きは、直前の実行の結果の上に立つことが多い。また、地の文の無いターンに畳む前の頼みを送ると、その答えが最後の地の文になり、本体に返す結果を置き換えてしまう。サブエージェントの文脈があふれたときは、Pi の compaction で続ける。

### プロンプトの線引き: 固定は仕組みの事実だけ、働き方は記憶のファイル

ADR-0008 の Decision（プロンプトは事実と環境だけを伝え、やり方は記憶か skill に任せる）を、サブエージェントと本体の両方について具体化する。runner が固定で持つ文は、エージェントに書き換えさせたくない仕組みの事実だけにし、ほかはエージェントが自分で直せる記憶のファイルで渡す。

- **runner が固定で持つサブエージェントのシステムプロンプト**: サブエージェントであること（本体に頼まれて動く）、目的と作業の場所、最後の地の文が本体に渡ること、問いで止まってよいこと、sandbox と Sentinel のこと、コネクタの一覧（ADR-0020）と skill の一覧、ツールの説明。人格（`personality.md`）・`always.md`・`handoff.md` は入れない。記憶の形も入れない。
- **サブエージェントの働き方**: 役割を選ばないときは、`/memory/agents/default.md` の本文を固定の文の後ろに足す。
- **役割のファイル**: `/memory/agents/<役割の名前>.md`。形は skill と同じで、先頭の front matter に `name`・`description`、本文は自由な Markdown である。役割を選んで起こすと、`default.md` の代わりにその本文を固定の文の後ろに足す。役割のファイルで決められるのはプロンプトの本文だけである。
- **本体の心得**: サブエージェントをいつ・どう使うかは、本体の skill `/memory/skills/subagents/SKILL.md` に書く。runner は特別に扱わず、ほかの skill と同じく一覧に載る。
- 本体のシステムプロンプトの記憶の骨組み（ADR-0008）に、`agents/` がサブエージェントの役割の置き場であり、`default.md` が役割を選ばないときに使われることを足す。
- `default.md`・役割のファイル・skill の最初の中身は、仕組みでは置かない。オーナーが最初のコミットで記憶に入れる。文面の種はこのリポジトリが持つ。入れた後は、エージェントのものである。

### サブエージェントと `/memory`

- サブエージェントが `/memory` に書くのを止める仕組みは作らない。既定のサブエージェントは、システムプロンプトで記憶の形を知らされない。記憶を渡したい役割は、役割のファイルの本文に書く。
- サブエージェントが書いたものも、ターンの終わりに backend がコミットする（ADR-0006）。誰が書いたかは、コミットの `agent` で分かる範囲でしか分からない。同じファイルへの書き込みは後勝ちになる。

### 失敗したときの倒し方

- 選んだ役割のファイルが無い、または front matter が読めないときは、サブエージェントを起こさず、`subagent_start` が理由を返す。違う役割で黙って走らせるより、本体が直して起こし直す方を採る。
- `default.md` が無い、または読めないときは、固定の文だけでサブエージェントを起こし、そのことを `subagent_start` の結果に添える。働き方のファイルが無いことでサブエージェントを起こせなくしない。
- サブエージェントの知らせを backend に入れられなかったときは、runner が同じ `id` で送り直す。runner が止まって送れなかった知らせは、立ち上がり直したときにサブエージェントの記録から送る。
- サブエージェントの通信も、ほかの外向きと同じく Sentinel を通る（ADR-0003）。守る対象（本物の鍵）と鍵の扱いは変えない。Sentinel の記録では、最初はサブエージェントを見分けない。どのサブエージェントの通信かは、時刻とそのサブエージェントの途中経過（`agent` 付きの `tool_call`）で突き合わせる。

### Web UI は見るだけ

- Web UI の右のパネルに、閉じていないサブエージェントの欄を並べる。欄には、名前・目的・状態・途中経過を出す。閉じたサブエージェントは欄から消える（記録には残る）。
- サブエージェントの途中経過は、会話の時系列には出さない。
- UI からサブエージェントを操作する口は作らない。オーナーが止めたいときは、本体に頼む。

### 本 ADR で決定しないこと

- サブエージェントの名前の形、`self-events` の `payload` の欄、`id` の番号の付け方、サブエージェントの状態を backend へ知らせる口の形（委譲先: [sandbox 向けの口の仕様書](../sandbox-api.md)）
- UI の流れでサブエージェントをどう見分け、閉じたサブエージェントをどう扱うかの形（委譲先: [UI 向けの API の仕様書](../ui-api.md)）
- サブエージェントを扱うツールの引数と説明の文面、サブエージェントの固定のシステムプロンプトの文面、サブエージェントの記録の置き場所（委譲先: runner のコード `packages/runner/src/prompts.ts` と `packages/runner/src/tools.ts`。ADR-0008 の方針に従う）
- サブエージェントごとに許す宛先を変える仕組み（サブエージェントごとのサロゲートか、プロセスごとの見分け）（委譲先: サブエージェントごとに宛先を絞りたくなったときの新しい ADR。ADR-0003 の「本 ADR で決定しないこと」に挙げた、既定を ask に切り替えるときの ADR と合わせて考える）
- UI からサブエージェントを操作すること（委譲先: [UI 向けの API の仕様書](../ui-api.md) と、操作を足すときの新しい ADR）
- 役割のファイルの front matter の拡張（モデル・thinking・道具の絞り込み）（委譲先: 要るようになったときの新しい ADR）
- 同時に走るサブエージェントの数の上限（委譲先: 資源が足りなくなったときの新しい ADR）
- `default.md` と `SKILL.md` の最初の文面（委譲先: リポジトリの `assets/memory-seed/`。入れた後はエージェントの記憶）

## Consequences

- 本体は長い作業をサブエージェントに預け、その間もオーナーと話せる。作業を並べられる。サブエージェントの途中経過は本体の文脈に積まれず、本体には最後の地の文の要約と場所だけが入る。
- サブエージェントとの往復は、ツールと出来事という既にある 2 つの仕組みに乗る。backend に増えるのは、サブエージェントの状態を UI に出すための記録だけで、サブエージェントの列は無い。
- サブエージェントの働き方も本体のサブエージェントの使い方も記憶のファイルなので、エージェントが自分で育てられる。runner の文を変えずに直せる。一方で、記憶が空のうちは、サブエージェントは固定の事実だけで動き、本体はサブエージェントの使い方を知らない。オーナーが最初の中身を入れることに頼る。
- サブエージェントは夜をまたいで残るので、閉じ忘れたサブエージェントのセッションと作業の場所が HOME に溜まる。片付けはエージェントの夜の振り返りに任せる。
- サブエージェントに割り込めないので、走っているサブエージェントの向きを変えるには、閉じて起こし直し、それまでの文脈を捨てることになる。
- 「結果か問いか」を runner が見分けないので、本体は止まったサブエージェントの地の文を読んで次を決める。
- サブエージェントが `/memory` に書くのは止まらない。既定のサブエージェントは記憶の形を知らないので書きにくいが、書けば本体と後勝ちで混ざり、日記が二重になることもありうる。
- サブエージェントのターンの終わりでもコミットするので、本体のターンの途中の変更が、そのターンの終わりより前にコミットされることがある。コミットのメッセージの `agent` は合図を送ったエージェントであり、書いたエージェントとは限らない。
- サブエージェントは同じサロゲートを持つので、サブエージェントに許す宛先を本体より狭くできない。どのサブエージェントの通信かを Sentinel の記録だけでは決められない。
- 上限を置かないので、サブエージェントを並べすぎると sandbox ごと OOM で落ち、本体も含めて中断する。

## Alternatives Considered

- **サブエージェントを同期で回し、終わるまでツールが返らない**: 本体がその間に出来事に答えられず、サブエージェントを並べられない。
- **サブエージェントが backend の出来事の列を持ち、本体からサブエージェントへも出来事で送る**: backend にサブエージェントごとの列と配送が要る。本体とサブエージェントは同じ runner の中にいるので、直接渡せば足りる。
- **サブエージェントにもオーナーへの返事の道具を渡す**: オーナーから見た相手が複数になり、誰と話しているかが分からなくなる。
- **サブエージェントを使い捨てにし、止まったら終わり**: 問いに答えて続けさせることができず、文脈を捨てて頼み直すことになる。
- **夜の切り替えでサブエージェントを閉じる**: 夜をまたぐ長い作業が切られる。閉じ忘れは夜の振り返りで片付ければ足りる。
- **サブエージェントに「問い」を知らせるツールを渡し、runner が結果と問いを見分ける**: サブエージェントに道具が 1 つ増え、本体はどちらにしても地の文を読む。
- **サブエージェントの働き方を runner の固定のプロンプトに書く**: エージェントが自分で直せない。ADR-0008 の方針に合わない。
- **サブエージェントが `/memory` に書けないようにする**: 書きたい役割（記憶の整理を手伝うサブエージェントなど）が作れない。書くかどうかは役割のファイルに任せる。
