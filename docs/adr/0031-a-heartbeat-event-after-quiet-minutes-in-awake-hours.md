# 0031. 起きている時間に何もない時間が続いたら、backend が heartbeat の出来事を入れる

- Date: 2026-11-16
- Status: Accepted（一部を [ADR-0055](0055-show-unfinished-work-in-heartbeats.md) で置き換え）

## Context

エージェントのターンは、出来事が届いたときにだけ始まる（ADR-0002）。オーナーのメッセージ、Slack、警報、予約、A2A の頼みが無ければ、エージェントは何もしない。自分で予約（cron の出来事）を入れておけば決まった時刻には起きられるが、予約は時刻に結び付いており、「しばらく何もない」ことには結び付かない。

オーナーは、とくに出来事が無くても、エージェントが自分から何かしら動くことを求めている。natsumi には、自分で予約する確認と、決まった間隔の合図（natsumi ADR 0014）があった。

前提になる事実は次のとおりである。

- backend は、起きている時間（設定）を持ち、`batch` の出来事を起きている時間の外には渡さない。夜の切り替えの時刻も backend が持つ（ADR-0007、ADR-0013）。
- エージェントの今の状態（ターンの最中か、待っているか）と、その状態になった時刻を、backend は途中経過の記録から引ける。
- 地の文を 1 つも書かずに終わったターンでは、畳む前に一度だけ頼みを送る（ADR-0015 の Decision 項 3（地の文の無いターンにだけ、畳む前に一度だけ頼む））。その分、モデルの呼び出しが 1 回増える。
- システムプロンプトは事実と環境だけを伝える（ADR-0008）。

## Decision

適用範囲は、エージェントの本体のセッションである。サブエージェント、夜の振り返りと整理係は対象ではない。

### 1. backend が、何もない時間が続いたら heartbeat の出来事を入れる

- 起きている時間に、本体の最後のターンの終わりから決めた時間がたち、その間に本体のターンが始まっていなければ、backend が heartbeat の出来事を 1 件入れる。
- heartbeat の出来事は backend の中の受信元とし、`delivery` は `now` とする。待っている `batch` の出来事は、ほかの `now` の出来事と同じく一緒に渡る（ADR-0013 の Decision 項 3（渡す時は受信元の側が出来事ごとに決める））。
- heartbeat のターンが終わると、そこからまた数える。何もない時間が続けば、決めた時間ごとに heartbeat が入る。
- 起きている時間の外、夜の切り替えの間、ターンの最中には入れない。
- 決めた時間は、配置の backend の設定で決める。設定が無ければ heartbeat は無い。

### 2. 何をするかはエージェントに任せる

[ADR-0055 残っている仕事は heartbeat の出来事にだけ載せる](0055-show-unfinished-work-in-heartbeats.md) で、無活動に加えて、残っている仕事があれば、その事実を載せる。heartbeat の発生条件や、畳む前の頼みの扱いは変えない。

- heartbeat の出来事が持つのは、何もない時間が続いたという事実だけである。何をすべきかは書かない。
- システムプロンプトには、heartbeat の出来事が何かを、事実として 1 文で書く（ADR-0008）。何もしないで終わってもよいかどうかなどの指図は書かない。
- heartbeat で何をするかは、オーナーかエージェントが記憶（`always.md` か skill）に書く。

### 3. ツールを使わずに終わった heartbeat のターンには、畳む前に頼まない

- heartbeat の出来事だけで始まったターンが、ツールを 1 つも呼ばずに終わったときは、地の文が無くても畳む前の頼みを送らない。ADR-0015 の Decision 項 3 の「頼まない」ターンに、これを足す。
- 理由は、そのターンでは何も起きていないので、畳んでも失うものが無いためである。何もない時間が続く日に、heartbeat のたびにモデルの呼び出しが 2 回になるのを避ける。
- heartbeat のターンでも、ツールを呼んだときは、ほかのターンと同じく ADR-0015 に従う。

### 本 ADR で決定しないこと

- 受信元の名前、出来事の `id`・`summary`・`payload`、設定の名前と既定（委譲先: [出来事の仕様書](../events.md) と [backend の仕様書](../backend.md) の「設定」）
- システムプロンプトの 1 文の文面（委譲先: プロンプトのファイル `packages/runner/src/prompts.ts`。ADR-0008 の方針に従う）
- heartbeat で何をするか（委譲先: エージェントの記憶。オーナーが `always.md` か skill に書く）
- 起きている時間の中で、時刻によって間隔を変えること（委譲先: 要るとなったときの新しい ADR）

## Consequences

- 出来事が無くても、エージェントは決めた間隔で起き、記憶に書いたこと（見回り、整理、自分の目標）を進められる。
- 何をするかが記憶にあるので、エージェントとオーナーが、heartbeat の使い方を育てられる。
- 一方で、heartbeat のたびにモデルを呼ぶ。何もせずに終わるターンでも、文脈の全体を送る（prefix cache が効く分は軽い）。間隔を短くするほど、費用が増える。
- 何もせずに終わった heartbeat のターンも、届いた出来事の行がセッションに残る。畳まれても、1 回につき出来事の 1 行の文脈を使う。
- ツールを使わずに終わった heartbeat のターンは、エージェントが何かを残したくても、地の文を書かない限り残らない。

## Alternatives Considered

- **エージェントが自分で予約（cron）を入れる**: 決まった時刻には起きられるが、オーナーと話していた直後でも起きてしまい、何もない時間とは結び付かない。
- **heartbeat の出来事に、何をするかの文を持たせる**: 指図がコードに入る。ADR-0008 の方針に合わない。
- **ツールを使わずに終わった heartbeat のターンにも、ADR-0015 のとおり頼む**: 何もない日に、heartbeat のたびに呼び出しが 1 回増え、残るものも無い。
