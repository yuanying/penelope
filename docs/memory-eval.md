# 記憶評価 CLI

`penelope-memory-eval` は、配置の役目に必要な問いに、対象の記憶だけを使ってどこまで答えられるかを確かめる CLI である（[ADR-0053](adr/0053-evaluate-memory-with-purpose-questions.md)）。合否は判定しない。Web UI や backend に問い・答え・結果を公開する口はない。

## 問いの書き方

現行の `/memory/PURPOSE.md` に次の形で書く。

```markdown
## 答えられるべき問い

- 定期点検では何を確認するか？
- 点検で異常が見つかったら、誰に報告するか？
```

見出しは `## 答えられるべき問い` とし、問いは重複のない `- ` で始まる箇条書きで、1 行に 1 問を書く。空行は無視し、次の `# ` または `## ` の見出しまでを読む。節の外にある箇条書きやコードフェンス内の見出しは問いにしない。現在と過去で問いを揃えるため、`--at` を指定しても問いは現行のファイルから読む。過去の記憶に `PURPOSE.md` がなくても評価できる。

## 実行と比較

Linux sandbox のコンテナ内で動かす。たとえば手元から `kubectl exec <pod> -c sandbox -- penelope-memory-eval` と実行する。以下はコンテナ内での引数の例。

```sh
penelope-memory-eval
penelope-memory-eval --at 0123456789abcdef --only 2
penelope-memory-eval --at 2026-11-20 --show
penelope-memory-eval --compare <左の結果ID> <右の結果ID>
penelope-memory-eval --compare <左の結果ID> <右の結果ID> --show
```

- 引数がなければ、未コミットの変更を含む現行の記憶で全問に答える。`--only NUMBER` は箇条書きの上から数えて 1 始まりの指定。
- `--at` は Git のコミットハッシュ（7 文字以上の一意な短縮形も可）、または UTC の日付 `YYYY-MM-DD` を受け取る。日付では `HEAD` の第一親をたどり、コミット時刻がその日の終わり以前である最初のコミットを選ぶ。現行の worktree・HEAD・index は切り替えない。
- `--compare` に結果ファイルの `.json` を除いた ID を 2 つ渡す。問いの文面が同じものを左右に並べ、片方にしかない問いはもう片方を `—` と表示する。比較は保存済みの結果を読むだけで、モデルを呼ばない。
- 既定で表示するのは問いの数、番号、モデルと思考の深さ、読んだファイルの数、道具の回数、トークン数、秒数と、評価時の結果のパス。問い・答え・読んだファイルの相対パスは `--show` を明示したときだけ表示する。

## 実行範囲と保存

問いごとに、人格や履歴、skill や拡張を引き継がないセッションをメモリ上に開く。評価開始時に日中の保存モデル設定を読み、保存したモデルがなければ、または候補から外れていれば、日中と同じ配置設定・Pi の既定に従う。記憶から読んだ情報は、日中と同じモデル経路の接続先へ送られる。

道具は `read`、`find`、`grep`、`ls` のみで、一時的に取り出した記憶のファイルを読む。`.git`、リンク、特殊ファイル、サブモジュールを道具には見せない。必要な問い、対象の記憶、または日中の保存設定を安全に読めなければ評価しない。現行記憶の写しはファイルごとに取得するので、本体による同時編集をまたいで単一時点の状態になるとは限らない。コミット単位で再現したい場合は `--at` を使う。

完了した評価は `$HOME/.penelope-memory-eval/<結果ID>.json`（ディレクトリ `0700`、ファイル `0600`）に保存する。バージョン、開始時刻、対象コミット（現行は `null`）、問いごとの本文・答え・内容を読んだファイルの相対パス・道具の実行回数・Pi が記録した合計トークン・回答に要した秒数・使用モデルと思考の深さを含む。`find`・`ls` で名前を列挙しただけのファイルは、内容を読んだファイルには数えない。保存した結果や `--show` の出力には私的な記憶が含まれ得るため、他人に渡すログには使わない。結果の保持と削除はオーナーが行う。
